# DeepSeek 文字闭环：配置与扩展

2026-09-20。真实接口已收到成功响应；首次真实测试在提纲格式校验失败后停止，未完成端到端创作。自动测试仍使用替代响应，不等同于真实模型质量验证。

## 最简单的使用方式

1. 打开项目根目录 `.env`，填写 `DEEPSEEK_API_KEY=你的密钥`，保存。不要分享密钥。文件已被 Git 忽略，网页不能下载它。
2. 停止旧服务（原终端 Ctrl+C），在项目目录重新运行 `python3 -m backend.web --port 8765`。
3. 打开 http://127.0.0.1:8765/，点“新建创作”，选择“真实 AI · DeepSeek”。旧模拟任务始终保持模拟。
4. 填主题、读者、风格与一小段真实素材；点“创建工作流”，再点“自动运行到人工处理”。
5. 查看每步结果；审核发现问题可改稿，复审后人工确认并导出 Markdown。

建议首条真实输入：主题“大学生整理课程资料”；读者“大一新生”；素材“我把文件夹按课程命名，并在文件名加入日期；这只是我的个人做法，没有统计效率变化”。第一次先用短素材，检查模型输出是否忠实，再增加长度。

“已配置”只检查本地存在 Key，不代表 Key 有效或有余额。API 返回错误会显示在页面，不会退回模拟结果。首次运行需网络连接与 DeepSeek 可用额度。无需新增 Python 依赖。

## 本轮执行范围

- 受众与研究并行各调用一次；Content 策略、提纲、开头、标题、正文各一次；Reviewer 一次。正常首次共 **8 次请求**，返修/补料会增加调用。
- 四角色用同一个模型、不同职责与输入输出；不是四份 API Key。文本 JSON 适配是 v0.3 的最小运行子集，尚未覆盖完整角色卡的所有工具、Skill 和长期 Memory。
- 模型：`deepseek-flash`；地址固定 `https://api.deepseek.com/chat/completions`；JSON 模式；关闭思考模式；输出最多 3000 Token；网络操作超时 90 秒。
- 同一步累计最多 3 次模型调用（含首次，不因补料/手动改稿重置）。初稿与所有自动返修合并计数，最多初稿 + 2 次改稿；第三轮审核仍需返修则 FAILED。接口异常、格式错误当前直接失败，**不会为了凑满3次自动重试**。审核调用也最多3次。
- 每任务最多 16 次模型请求、40000 Token。请求前按 UTF-8 字节数加输出和消息开销预留，响应后按供应商返回用量结算；长素材或上下文可能提前触发预算停止，不静默截断素材。
- 保守估算费用上限：每任务 $0.10、整个本机服务每 UTC 日 $0.50。按每百万 Token $1.20 统一上界估算（高于当日公布输入单价，采用输出峰时单价），缓存与非峰时优惠不计。页面不是精确账单；价格变更需同步更新 `backend/provider.py`，不能承诺供应商账单硬上限。
- 实际网络调用在数据库事务外；先保存步骤占用与预算，防止刷新、双击或重复命令重复收费。失败不自动重试；并行分支失败时，另一个已发请求可能仍产生用量。
- 中断后不自动重放不确定请求。服务重启后未决步骤保留“请求中/中断”记录，需取消后新建；这是最小版本，尚无后台队列、租约自动恢复或增量流式输出。
- 可在网页查看调用记录、Token、用量未知的预算预留、阶段输入输出及错误。取消不能撤销供应商已经接收的请求，但晚到结果不会覆盖已取消任务。
- Reviewer 输出须符合八项检查和旧问题逐项复核契约。引用需匹配用户原文，稿件版本与哈希由服务端绑定；匹配仅证明字符串存在，不能证明素材真实或检查完整。未接全网查重、外部事实检索或正式平台规则服务。

默认空 Key；真实模式需用户明确创建并执行任务。设计机器契约中的 `paid_provider_enabled=false` 仍表示默认禁用；本机适配在配置 Key 且用户选择 live 后显式启用。不能将此适配视为完整生产预算/部署方案。

## 图片和 PDF 如何扩展

当前 `backend/live.py:material_records()` 把输入转换为带 `source_id / source_type / text / verification / page` 的材料记录；模型与四角色只消费记录。

后续新增上传接口和独立解析模块即可：

| 输入 | 解析模块 | 交给 Agent 的数据 | 额外工作 |
| --- | --- | --- | --- |
| 文本 | 现有文字适配 | 原文、来源 ID | 已接入 |
| PDF | 文本抽取；扫描件 OCR | 按页文本、页码、原文件引用 | 上传大小/页数限制、失败提示、人工纠错 |
| 图片 | 图片识别/视觉模型 | 图片描述、识别文字、原图引用 | 图片预览、识别结果确认、调用预算 |

还需要文件存储、访问隔离、解析状态 UI、引用预览与测试。这些尚未实现；新增输入通常不必重写四角色流程。**图片输入**和**生成封面/图文导出**是两类独立功能。

## 后续多供应商方案（尚未实现）

一个 DeepSeek Key 可供四个 Agent 共用。不同供应商一般各自配置 Key；不是每个 Agent 必须有单独的 Key。后续按角色选择供应商与模型，例如研究、创作、审核各用不同模型。

保留统一 complete 接口，为 Qwen/Kimi 分别添加适配器处理地址、JSON/思考模式差异、错误码与用量字段；角色路由只决定调用哪个适配器。调用3次上限和整单预算仍放在编排层，换模型或换 Key 不得重置计数，不自动向另一个供应商重发失败资料。价格需按供应商/模型配置，不能沿用 DeepSeek 单价。

接入成本可控，稳定运行还需要每家的契约与异常测试。收益未验证：先用同一组少量任务比较输出采用率、修改量、时延与费用，只有某个阶段有明显改善再切换，不必同时让多家模型生成同一份稿件。

参考：[通义千问兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[Kimi 提示与任务拆分指南](https://platform.moonshot.ai/docs/guide/prompt-best-practice)。
