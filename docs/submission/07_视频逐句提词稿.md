## 一 录制前 10 分钟准备

1. 用**独立测试账号**（不要用自己日常账号），确认账号档案里没有真实姓名、学校、手机号。
2. 资料库只留本次要演示的两三份资料：`示例产品资料.txt` 一份即可，其余移出，避免画面出现无关真实资料。
3. 模型连接先点一次「测试连接」，确认 Key 有效、余额够；预算上限设小一点（例如 1 元）。
4. 桌面清空：关掉微信、邮件、网盘、浏览器书签栏，图标不要出现真实姓名或单位。
5. 浏览器缩放 100%，窗口 1920×1080；系统语言与输入法切到英文，避免输入法候选框挡住画面。
6. 提前把「模拟模式」和「真实模式」两个任务各跑通一次，确认按钮位置一致。

## 二 逐句台词（照念）

### 镜头 1｜0:00—0:25　片头与问题

**画面**：软件工作台首页（运营总览或创作首页），鼠标缓慢移动到左上角作品名。

> 大家好，这是有迹，一个面向个人创作者的多智能体创作与运营助手。
> 它要解决的问题很具体：写一篇带事实的内容时，依据容易丢、版本容易乱、失败容易失控。
> 接下来四分钟，我用一次真实的创作，演示它怎么把这三件事管住。

**停顿**：说完第三句停 1 秒，再切画面。

### 镜头 2｜0:25—0:55　资料入库与三组检索

**画面**：资料库 → 上传 `示例产品资料.txt` → 预览 → 选择用途「事实」→ 确认入库 → 搜索「35 mL」→ 展开来源原文与位置。

> 先看资料库。导入之后可以先预览、校对，确认了才入库，原文、版本、页码和位置都会留下来。
> 入库时要选一个用途：事实、写法参考，或者通用方法。这个选择决定了它进入哪一组检索——写法参考永远进不了事实引用位。
> 我搜一下「35 毫升」，可以看到命中的原文片段、它来自哪份资料的第几页。

**提示**：搜索时不要剪掉输入过程，让观众看到是真实检索。

### 镜头 3｜0:55—1:45　四角色创作

**画面**：创作工作台 → 选账号与平台 → 填主题「介绍示例保湿乳的产品信息与使用注意」→ 勾选资料 → 选择**模拟模式**（画面出现「模拟」标注）→ 提交后台运行 → 展开受众洞察、素材研究两个并行分支 → 展示策略、提纲、开头、标题、正文的过程产物。

> 接下来是创作工作台。选账号、选平台，填主题：介绍示例保湿乳的产品信息与使用注意。
> 勾选这次允许使用的资料，提交后台运行。这里能看到四个角色：受众洞察和素材研究基于同一份快照并行执行，然后内容角色依次给出策略、提纲、开头、标题和正文，最后是主编审核。
> 每个阶段的产物都会落库，所以关掉浏览器，任务也会继续跑。
> 现在演示的是模拟模式，只用来看流程，不代表模型的真实写作质量——真实模式我稍后单独说明。

**提示**：这一段画面事件较多，等待时间可以用「加 1.5 倍速」处理，并在角落标注「画面加速，非瞬时生成」。

### 镜头 4｜1:45—2:35　审核、引用校验与返修（真实模式）

**画面**：切到**真实 AI 模式**的任务 → 审核结果面板 → 逐条展开引用校验（来源存在 / 逐字命中 / 审核指向句在稿）→ 修改标题 → 出现新版本、旧审核失效提示 → 触发返修 → 复审结果。

> 审核结果出来了。这里的每一条引用都要过三层程序校验：来源必须在本次快照里、引文必须是原文的逐字子串、审核意见指向的句子必须真的出现在当前稿件里。
> 所以模型说「通过」不算通过，服务端还要核对必过项、稿件版本和审核有效期。
> 我现在把标题改一下，就会产生一个新版本，旧审核立刻失效，必须重新审核。
> 这是返修：上一轮的意见会带着新版本再走一遍复审，通过之后才允许确认。

**提示**：真实模式这一段是本片的可信度核心，宁可多花 20 秒，也不要剪成「一点就出」。

### 镜头 5｜2:35—3:00　确认与导出

**画面**：版本比较 → 确认当前版本 → 下载 Word 确认稿 → 用 Word/WPS 打开，展示标题、正文、互动引导、标签与确认方式标注。

> 确认之后可以导出。Markdown，或者可编辑的 Word 确认稿——标题、正文、互动引导、标签都在里面。
> 确认只代表你接受这一版，不代表平台已经发布；发布动作还是由你在平台里完成。

### 镜头 6｜3:00—3:35　发布记录与运营复盘

**画面**：发布归档 → 回填链接与时间 → 指标页录入 24/72/7 天数据（画面有「模拟」标注）→ 复盘页：观察 / 假设 / 实验建议 → 采纳经验 → 周计划。

> 发布之后回到这里回填链接和指标：24 小时、72 小时、7 天。
> 系统只做同口径的比较：同账号、同平台、同形式、同来源、同窗口。
> 输出的是观察、可能的解释，和一个单变量的实验建议，不做因果归因。
> 这几条数据是模拟的，画面上有标注；真实的运营数据需要你自己回填。

### 镜头 7｜3:35—3:50　技术贡献与效果

**画面**：切到一张静态页（可用答辩 PPT 第 6 页或第 14 页）：三组检索、引用闭环、内容风洞 + 37.5% → 64.1%。

> 技术上有三件真正花力气的事：三组解耦的证据检索、主张级引用闭环、还有把读者反馈变成可复查补丁的内容风洞。
> 在十八次真实模型对照里，检索组的事实支撑率是百分之六十四点一，单次直写是百分之三十七点五。

## 三 失败预案

| 现场情况 | 处理方式 |
| --- | --- |
| 模型接口超时 | 停下等待，如实保留等待画面并加速播放，标注「网络等待」；不要剪成瞬间完成 |
| 余额或 Key 失效 | 切模拟模式完成剩余镜头，在片尾字幕写明「真实模式因额度原因未演示」 |
| 页面报错 | 保留报错画面 + 修复后重录一次；不要把报错剪掉伪装成功 |
| 时间超了 | 优先压缩镜头 3 的等待与镜头 6 的录入过程，不要压缩镜头 4 的校验 |
