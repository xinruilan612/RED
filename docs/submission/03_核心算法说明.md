## 一、问题定义与输入输出

任务输入包括创作主题、目标读者、风格、本次授权资料、目标平台与账号档案。资料检索返回有限原文片段，服务端保存来源标识、版本、页码与字符位置，形成不可随意替换的**冻结检索快照**。模型输出依次为角色分析、策略、提纲、开头、标题、正文与审核报告。

最终产物是**带有有效审核与人工确认的稿件版本**。系统优化的目标不是「写得像爆款」，而是三条可验证的约束：

1. **有依据**：可核查主张应当能追溯到本次授权资料或用户素材。
2. **不越界**：资料声明缺失的维度（时长、功效、承重、价格等）不得被写成结论。
3. **可追溯**：每一版稿件的输入、检索结果、审核意见与费用都能回查。

系统以「有依据、不越界、可追溯」作为优化目标，不以流量指标作为设计依据：稿件的价值由可核对的依据与读者的真实反馈判定，而不是由一次生成的速度判定。

## 二、三组解耦的分类证据检索

### （一）为什么不是普通 RAG

普通 RAG 把所有资料放进同一个向量池检索，在实际内容创作中会产生一个具体错误：**「写法参考」被当成「事实依据」引用**。参考他人的表达结构是正当的，把他人的产品结论搬进自己的稿件是错误陈述。

本软件按**证据角色**把资料解耦成三组，各自有独立的过滤条件、检索语义、配额与降级路径，再分别进入不同角色的上下文。

### （二）证据角色与过滤条件

| 组 | 角色 | 允许进入的条件 | 不允许进入的条件 |
| --- | --- | --- | --- |
| `methods` 方法 | 通用写作方法 | 当前领域**或**通用领域；渠道与形式适用（`any` 可通配） | 其他领域专用方法 |
| `examples` 样例 | 写法参考 | 与任务领域**至少有一个交集**，且渠道、形式**完全匹配** | 跨领域样例；渠道或形式不符的样例 |
| `facts` 事实 | 可核查材料 | 限当前账号、有效版本、用户所选资料；主题相关 | 表达参考类资料；私密或好友可见笔记；未读摘要 |

三个角色边界之外还有一条硬规则：**样例与方法永远不能充当事实引用位**。研究角色输出的 `source_id` 必须来自 `facts` 组或用户本次素材，否则被服务端拒绝。

### （三）检索前过滤：先授权，再计算

所有过滤在向量计算**之前**完成，顺序为：

```
owner/account 隔离 → 资料有效状态 → 图谱可见性 → 证据角色
→ 领域交集 → 渠道/形式 → 所选资料 → 事实主题门控 → 向量召回
```

这一顺序有三个实际收益：

- **不越权**：其他账号的资料在进入候选集之前就被排除，不会被算进相似度。
- **不浪费**：向量只对已授权的候选子集编码。
- **可解释**：每一组的实际过滤条件与候选数被冻结进任务快照，事后可回查「这篇稿子的依据是怎么选出来的」。

**产品型号精确匹配**：当查询中出现型号类标识（字母与数字组合）时，`facts` 组候选必须**包含全部型号串**，否则淘汰。这阻止了「A 型号的参数」被移植到「B 型号」。

**事实主题门控**：`facts` 候选还需通过词项校验——与查询的词项交集为空、或长查询（>3 词）命中不足 2 个词、或覆盖率低于 10%，直接淘汰。避免长问题里偶然的双字词匹配被当成相关。

### （四）向量召回与确定性二次重排

对已过滤候选，使用本地预训练中文向量模型（默认 `bge-small-zh-v1.5`）批量编码，归一化后按余弦相似度召回。编码分批进行，批大小受上限约束，向量带 LRU 缓存。

最终排序分数为**确定性线性组合**：

```text
rank_score = 0.8 × cosine_similarity + 0.2 × term_coverage
```

其中 `term_coverage` 是查询词项在片段中的覆盖率。三组使用不同的检索查询构造：

| 组 | 检索查询 |
| --- | --- |
| `facts` | 用户原始主题 |
| `methods` | 形式标签 + 通用写作结构词 |
| `examples` | 领域标签 + 形式标签 + 结构词 |

**这是确定性的二次重排，不是交叉编码器（cross-encoder）。** 0.8/0.2 的权重为工程取值，可直接替换为学习式重排；替换前后用同一批固定样本与同一套指标做消融对照（计划见技术方案第五章（四）），本文不把工程取值写成学习到的参数。

### （五）分级降级与诚实标记

系统不假设向量模型一定可用。三组各自独立降级：

- 某组向量计算失败 → **该组**在**已通过全部过滤**的候选内改用真实中文 BM25，并记录 `retrieval_mode=bm25`、`semantic_score=null`。
- 同一组内已算出的部分批次向量**全部丢弃**，绝不把「部分向量结果」标成完整语义检索。
- **正常向量检索零命中不触发词项补齐**：宁可留空并记录缺口，也不借其他领域的样例或无关片段补齐。
- 每组的 `vector_candidate_count` 与 `lexical_candidate_count` 分开记录。

任务快照中的引擎标识只有三种，与真实执行路径一一对应：

```text
filtered-bm25-zh-bigram-v1              纯词项
filtered-local-vector-rerank-v1         纯向量
filtered-local-vector-bm25-fallback-v1  混合降级
```

**部署形态与引擎标记**：本地向量模型约 95MB，作为可部署组件提供。部署方提供模型目录时启用语义检索；未提供时按组自动使用纯词项引擎，并在界面与任务快照中标注实际引擎标识。无论哪种形态，BM25 结果都不会被展示成语义检索结果——引擎标识由执行路径决定，不由界面文案决定。

### （六）中文 BM25 基线

词项索引对英文与数字提取小写词项，对连续中文提取相邻双字词，单汉字单独保留。文本按页切成**最长 800 字符**的片段，**步长 650 字符**（重叠 150 字符），保留原始位置。

```text
IDF(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
score(d,Q) = Σ_t IDF(t) · [2.2 · f(t,d)]
             / [f(t,d) + 1.2 · (0.25 + 0.75 · L(d)/avgL)]
```

对应 BM25 参数 k1=1.2、b=0.75；实现用 `max(1, avgL)` 防止空集合除零。查询词超过 3 个而片段仅命中 1 个词时排除。

### （七）配额、上下文与复杂度

| 项 | 取值 |
| --- | --- |
| 每组条数上限 | 方法 2 / 样例 3 / 事实 4 |
| 单片段字符上限 | 700 |
| 三组总字符预算 | 5,200 |
| 单任务事实资料选择 | 最多 3 份 |

配额是工程约束，用于控制上下文成本并防止单组挤占其他组，不是最优解。

复杂度：设已过滤片段数为 N、查询词数为 q，词项路径的文档频率统计与评分为 O(N·q)，排序 O(N log N)；向量路径为两次批量编码加上 O(N log N) 排序。以上为代码结构分析，不是性能实测。

## 三、主张级引用闭环

### （一）三层程序校验

模型输出的每一处引用都要通过服务端逐层校验，任何一层失败即拒绝该输出：

```text
① source_id 必须存在于本次冻结快照
② quote 必须是该来源正文的逐字子串
③ 审核 claim_map 中的 excerpt 必须出现在当前稿件正文中
```

第三层把「审核意见指向哪句话」与「稿件实际写了什么」绑定，因此模型不能凭想象生成审核条目。

### （二）审核不是最终权限

模型返回 `approved` **不等于**稿件通过。服务端另有一组守卫：

- 必过检查项是否齐全；
- 审核是否绑定**当前**稿件版本与内容哈希；
- 是否存在未解决的高严重度问题；
- 稿件是否有有效快照。

人工修改后旧审核立即失效，必须复审；过期 Worker 不能提交覆盖新版本的结果。

### （三）无依据时收窄，而不是补造

当研究角色判定核心事实缺口存在时：

- 允许继续生成，但提示词要求**按已有信息收窄选题、标题承诺与正文范围**；
- 不得补造规格、价格、功效或个人经历；
- 审核即使自述通过，也会被保守记录为需要人工处理；
- 最终由用户明确「人工采用」后才能导出，并在文档中标注未通过 AI 审核。

### （四）已知边界

逐字匹配证明的是**引用位置存在**：这句话确实来自这份资料。论证是否成立、来源是否权威、内容是否原创，由人工最终确认把关。系统因此把「程序校验」与「人工确认」设计成两道独立关口，而不是用一道替代另一道。

## 四、多角色协作与停止控制

### （一）执行图

```text
固定输入快照与模型路由
  ├─ audience（受众与选题）┐
  └─ research（资料与事实）┤ 并行
                          ↓ 汇合
  strategy → outline → hook → title → body
                          ↓
                       reviewer
                    ├─ approved → 人工确认
                    ├─ revision_required → revise → 复审
                    └─ 事实缺口 → 等待用户补料
```

受众与素材研究基于**同一冻结快照**并行执行；内容阶段顺序推进；审核不通过进入返修并复审。人工改稿产生新版本后重新进入审核。

### （二）有界停止

| 项 | 上限 |
| --- | --- |
| 单阶段尝试 | 3 次 |
| 返修轮次 | 2 轮 |
| 补料轮次 | 1 轮 |
| 单任务调用 | 24 次 |
| 单任务 Token | 160,000 |
| 单次输出 Token | 3,000 |
| 单阶段超时 | 180 秒 |

调用前持久预留费用与 Token；**用量未知时不重发**，保留账本并阻断后续请求，等待人工核对。

### （三）恢复一致性

节点幂等键包含快照、轮次、阶段与适用稿件版本；节点记录与业务产物同事务提交。任务租约为30秒，心跳为10秒，fencing token 拒绝旧 Worker 提交。已收到响应可在恢复时复用；请求已发出而响应未落盘时无法确定外部费用，系统阻断，不承诺外部调用恰好一次。

## 五、内容风洞：可追溯的写作改进协议

常规「AI 改稿」有三个答不上的问题：读者哪里没看懂、资料到底支持不支持、改完到底有没有变好。内容风洞把这三个问题拆成四个可审计阶段：

```text
wt_conditions（作者设定必须答对的问题）
    → wt_read（只依据当前稿件判断是否讲清楚）
    → wt_verify（用材料核验答案是否有依据）
    → wt_patch（只对作者选定的问题生成局部补丁）
    → 原条件复查（保留未解决项）
```

### （一）用 ID 代替文本的间接层

| ID | 作用 |
| --- | --- |
| `span_id` | 把稿件切成可定位的段落槽位；模型只能**选择**槽位，不能计算字符偏移 |
| `excerpt_id` | 把当前稿件切成读稿证据片；答案必须引用 ID，程序提取原文 |
| `evidence_id` | 把材料切成证据片；核验时必须引用 ID |

模型不输出引用文本，只输出 ID，由程序取原文比对。这消除了「改写引文、拼接分散句子、添加省略号」这类看似引用了实则没有的错误。

### （二）阶段约束

- **读稿**只允许 `pass` / `unclear`；`pass` 必须给出有效 `excerpt_id`。
- **核验**阶段：只要读稿是 `unclear`，本条必须 `unclear`，**即使材料里有答案**；材料矛盾记 `unsupported`，材料无依据记 `insufficient`。
- **补丁**最多 8 处，每处必须绑定 `span_id` + 逐字复制的 `original`，`replacement` 必须是可直接阅读的正文，禁止占位符。
- 无资料依据时返回空补丁，**不制造通过**；复查保留未解决项。

### （三）与普通改稿的差别

| | 普通 AI 改稿 | 内容风洞 |
| --- | --- | --- |
| 问题来源 | 模型自行判断 | 作者确认的具体问题 |
| 修改位置 | 模型自由发挥 | 绑定 `span_id` |
| 依据 | 模型知识 | 绑定 `evidence_id` |
| 验收 | 再问一遍模型 | 用原条件复查，未解决项保留 |
| 无依据时 | 倾向补写 | 返回空补丁 |

内容风洞已完成研究协议、多轮真实模型回归与产品化接入：作为独立「内容风洞」页面，可导入已有稿件、选择模拟或真实 AI 模式，开展条件设定、读稿、核验、补丁与复查，并导出报告。

**实测记录（2026-10-21，真实模型）**：P20 Ultra 尺寸稿设定 12 条条件，原稿 4 条通过、8 条未讲清；首次读稿 5/5 判为 `unclear`；生成 1 个实质补丁后，同条件复查 2 条 `pass`、3 条保留未解决——系统如实保留了未解决项，没有把复查做成「全部通过」。

**代理读者盲评（2026-10-07，六个独立代理 × 18 次阅读）**：三篇人为删节控制稿的答案定位从原稿 **0/45** 提升到风洞稿 **32/45**；完整任务成功率两组均为 0/9。因此本文只主张「定位到答案的能力提升」，不主张「完整任务成功率提升」——这是同一组数据能支持与不能支持的两件事，分开写。

## 六、描述性运营分析

运营分析是确定性规则执行器，不调用收费模型。对阅读/播放量 v 和某项互动次数 x：

```text
r = 1000 · x / v   （仅当 v 非零且 x 已知）
```

基线只选择同账号、同平台、同形式、同流量类型、同来源、更早且已观测的作品；观察窗口为 24 / 72 / 168 小时，容许实际观察时长为目标的 100%–125%；某指标至少 3 条可用历史才展示中位数，该门槛不保证统计充分。

输出为观察、可能解释与单变量实验建议，**不作因果归因**。指标修正会使依赖它的分析与经验失效；经验撤销会使引用它的计划转为需复查。经验只在同平台、同账号、同来源模式内复用，不是在线参数训练。

## 七、评测方法：三组对照

### （一）三组配置

| 组 | 配置 | 材料去向 |
| --- | --- | --- |
| A | 单次模型调用完成全部输出；无检索、无多角色 | 材料拼入单条提示词 |
| B | 生产四角色流程；检索关闭 | 材料作为任务背景 |
| C | 生产四角色流程；三组分类检索开启 | 材料入库后按分类检索 |

同一模型、同一素材、同一预算上限、同一天内执行，记录代码哈希与提示词版本。

### （二）六个指标（离线可复算）

| 指标 | 定义 | 方向 |
| --- | --- | --- |
| 事实支撑率 | 有冻结来源支撑的可核查句 ÷ 可核查句总数 | 越高越好 |
| 禁用断言率 | 命中禁用断言模式的稿件数 ÷ 稿件总数 | 越低越好 |
| 要点覆盖率 | 命中的预注册要点数 ÷ 要点总数 | 越高越好 |
| 人工修改率 | 人工修改字数 ÷ 成稿字数 | 越低越好 |
| 返修轮次 | 审核触发返修的次数 | 观察项 |
| 成本与耗时 | Token、费用上界、各阶段墙钟耗时 | 观察项 |

指标实现为确定性纯函数，不联网、不调模型，任何人可用同一份结果文件复算。评测题库与评分标准在实验开始前冻结。

### （三）实验结果（2026-10-18，真实模型）

题库 G01–G06 六题 × 三组共 18 次运行全部成功，模型 `qwen-plus`，总成本 0.384 美元。结果如下：

| 组 | n | 事实支撑率 | 要点覆盖率 | 禁用断言率 | 平均正文字数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A 单次直写 | 6 | 37.5% | 83.3% | 0.0% | 197 |
| B 多 Agent · 关检索 | 6 | 52.8% | 65.6% | 0.0% | 164 |
| C 多 Agent · 分类检索 | 6 | **64.1%** | 65.8% | 0.0% | 159 |

**归因拆解**：多角色结构带来 +15.3 个百分点（B − A），分类检索再带来 +11.3 个百分点（C − B），合计 **+26.6pp（1.7 倍）**。成本上 C 约为 A 的 53 倍，相对 B 只贵 14%。

**被推翻的预期如实保留**：B 的要点覆盖率低于 A（65.6% vs 83.3%），即单次直写覆盖面更完整；C 的禁用断言率并未低于 A（两组均为 0）。

**关键定性发现**：G05 一题故意不提供任何事实资料。A 组编造出三个色号与包装细节，B、C 两组均明确声明资料缺失、以实物为准。**自动指标没有抓到这次编造**，因为答题前预注册的禁用模式未预见到这种形态——这一盲区已记录，不能把「0 命中」表述为「无事实错误」。

**边界**：n=6，仅为初步观察，不构成统计结论；本实验不测量真人读者偏好、爆款率或流量。要点覆盖率使用词项重叠，对同义改写敏感，只用于组间比较。

## 八、验证范围与评测口径

工程验证覆盖：真实数据库隔离、来源一致性、并行分支恢复、错误审核拒绝、调用审计、崩溃后重启不重复计费、取消不被迟到结果覆盖。模型使用测试替身时，验证的是守卫行为而非生成质量；生成质量由第七节的三组真实模型对照与内容风洞实测回答。

评测口径分三层，避免用一层的结论替代另一层：

| 层 | 回答什么 | 证据 |
| --- | --- | --- |
| 行为契约层 | 系统会不会乱来（状态、权限、幂等、预算、恢复） | 1189 项后端与 256 项前端自动化测试 |
| 指标层 | 多角色与检索是否真的提高依据覆盖 | 18 次真实模型对照，事实支撑率 37.5% → 64.1% |
| 协议层 | 改稿是否真的让读者看懂 | 12 条条件实验与 18 次代理盲评（0/45 → 32/45） |

三层的边界不互相顶替：合同测试不证明生成质量，指标不证明读者偏好，代理盲评不证明真人偏好。使用结论时应指明层级。
