# 有迹核心算法说明

AI+软件创新 | 团队编号 47191919 | 软件版本 0.7.0

本软件采用第三方预训练大语言模型完成受众分析、创作和审核，采用 BM25 从用户资料中检索相关原文。项目自行实现角色间的数据交接、证据和稿件版本约束、费用控制及描述性运营分析。本说明阐述算法在软件中的应用，不主张基础模型、BM25或LangGraph为团队原创。

## 一 问题定义与输入输出

任务输入包括创作主题、目标读者、风格、素材、目标平台、账号档案与适用历史。资料检索返回有限原文片段，服务器保存来源标识、版本和位置，形成不可随意替换的任务快照。模型输出依次为角色分析、策略、提纲、开头、标题候选、正文和审核报告。

最终产物是具有有效审核和人工确认的稿件版本。优化方向是减少无依据陈述和人工返工，并控制成本；当前没有已测得的统一最优目标函数或传播预测准确率。

## 二 BM25 原文检索

### 2.1 文本处理

backend/knowledge.py 对英文和数字提取小写词项，对连续中文提取相邻双字词；单个汉字单独保留。按页将文本切为最长800字符的片段，步长650字符，保留150字符重叠区域和原始位置。它是词项索引，不是嵌入向量。

查询只遍历同一 owner、account_id 下有效资料的当前版本片段。查询词去重形成集合Q；N为片段数，df(t)为包含词项t的片段数，f(t,d)为词频，L(d)为片段词项总数，avgL为平均词项数。

### 2.2 与代码一致的评分

```text
IDF(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
score(d,Q) = sum_t IDF(t) * [2.2 * f(t,d)] /
                 [f(t,d) + 1.2 * (0.25 + 0.75 * L(d)/avgL)]
```

求和只包含查询与片段共有的词项，对应BM25参数k1=1.2、b=0.75；代码使用max(1,avgL)防止空集合除零。查询词超过3个但片段仅命中1个词时排除，避免长问题中偶然双字词匹配。该阈值是当前工程启发式，尚无消融实验支持最优性。

## 二 BM25 原文检索 续

### 2.3 排序和证据快照

结果按分数降序、source_id次序排序，默认选取最多4段。每段找到最早命中位置，从其前最多100字符开始截取最多400字符，并同步调整offset。匹配分数只表示相关度，不是事实可信度。

检索记录保存查询与所选source_id；任务进一步固定资料版本和原文，四角色读取同一快照。停用资料不再进入新检索，旧任务继续保留原证据。空结果明确为insufficient，不能自动捏造补齐。

当前实现每次检索在账号候选集合上计算词频与文档频率，无倒排索引或语义召回。若片段数为N、查询词数为q，文档频率统计和评分主要随N与q增长，排序最多为O(N log N)，同时存在读取词项字典的成本。上述为代码结构分析，不是性能实测。

## 三 大模型应用与结构化约束

### 3.1 模型和输入组织

backend/provider.py 当前默认模型标识为deepseek-flash。实际模型由配置和任务路由确定，新任务冻结路由与提示词版本。本文不据此宣称模型可用性或供应商价格始终不变。模型通过现有API推理，本项目未训练或微调模型。

每次请求由系统阶段指令和结构化用户数据组成。数据包含Brief与materials；下游阶段再附加branches和upstream；审核或返修附加当前draft及适用旧审核。账号历史和偏好放在operations字段。外部资料作为待分析数据，不能成为执行指令。

### 3.2 各阶段输出

| 阶段 | 主要结构和限制 |
| --- | --- |
| audience | 受众、依据、痛点与机会；缺少历史时明确为假设 |
| research | facts为source_id与quote；缺口及禁止断言单列 |
| strategy与outline | 两个候选角度；提纲items为2至8个非空字符串 |
| hook与title | 开头文字；5个标题及对应比较理由，selected来自候选 |
| body与revise | selected_title、body、cta、tags；返修基于审核意见 |
| review | 检查项、问题、claim_map、限制及后续动作 |

JSON解析和类型校验拒绝不合格输出。系统提示提出的风格或长度要求并非全部等同于确定性硬校验；实际校验以normalize和契约函数为准。

## 四 多角色协作与审核返修

### 4.1 执行过程

受众和研究分支并行，成功后汇合。content顺序执行strategy、outline、hook、title、body，再由reviewer审核。审核需要修改时进入revise并复审；需要事实补充时等待用户。模拟分支用模板验证流程，真实模式通过统一Calls入口调用模型。

简化流程如下。该伪代码用于解释控制过程，实际代码还包含权限、事务、预算及异常处理。

```text
固定输入快照与模型路由
并行执行 audience 和 research 并校验结果
若存在必须补充的事实 则等待用户
按顺序执行 strategy outline hook title body
审核当前稿件
若需要返修且预算允许 则返修并再次审核
若审核通过 则等待人工确认准确版本
人工编辑产生新版本 并重新进入审核
```

### 4.2 引用检查与批准

研究输出的source_id必须存在，quote必须为相应来源原文的非空子串；审核claim_map中的excerpt还必须出现在当前稿件中。backend/live.py中的verify_quotes执行这些检查。逐字匹配能证明引用位置存在，不能自动证明论证成立、资料权威或内容原创。

模型返回approved不直接获得批准权限，服务器检查必过项、稿件引用与有效审核。Run.accept核对具体稿件、审核和快照。人工修改后的旧审核不能复用，过期Worker也不能提交覆盖。

### 4.3 停止与恢复

单阶段累计最多3次，初稿与自动返修合计最多3轮，整单最多16次调用与40,000 Token，并受费用上限约束。实际失败不意味着自动重试；接口错误、格式错误和未知付费用量均有停止路径，计数不会因手工改稿而无限重置。

节点幂等键包含快照、轮次、阶段及适用稿件版本，节点记录与业务产物同事务提交。租约为30秒，心跳10秒；fencing token拒绝旧Worker提交。模型响应先保存，可在后续恢复时复用。请求已发出而响应未落盘时无法确定外部费用，系统阻断，不承诺外部调用恰好一次。

## 五 运营分析与可撤销经验

backend/analytics.py中的AnalyticsAgent是确定性规则执行器，不调用收费模型。对阅读或播放量v、某项互动次数x，计算每千次阅读或播放的指标r=1000x/v。仅当v非零且x已知时计算；总互动要求点赞、收藏、评论、分享均已知。次数不等于去重人数。

基线仅选择同账号、平台、形式、流量类型、数据来源及观察窗口的更早作品，排除当时尚未观测的数据。观察窗口为24、72、168小时，容许实际观察时长为目标的100%至125%。各指标至少3条可用历史才展示中位数，该门槛不保证统计充分性。

分析输出观察、可能解释和单变量实验建议，不作因果归因。指标修正会使依赖它的分析和经验失效；经验撤销会使引用它的计划转为需复查。经验只在同平台、账号及来源模式内复用，不是在线参数训练。

## 六 验证方法和已知限制

本次工程回归覆盖真实数据库、来源一致性、分支恢复、错误审核拒绝和调用审计，详见测试报告。历史真实模型记录只有单条虚构场景试运行，无法计算广泛任务质量、真实传播收益或稳定成功率。

下一步拟使用经授权的多类真实需求，以相同模型、材料和预算比较单次生成、无检索协作和有检索协作。预先规定评分尺度，由人工核对资料支撑、表达适配及修改量，记录耗时与费用并保留失败案例。该实验尚未执行，不填写预测结果。

主要限制包括关键词不能覆盖所有语义表达、没有自动繁简转换、原文引用检查不能取代事实核查、模型审核存在误判、手工指标未经平台核实。复杂协作可能增加调用成本，其收益须通过对照数据证明。
