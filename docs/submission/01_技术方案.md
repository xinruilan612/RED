## 一 产品概述与定位

### 1.1 背景与目标

小品牌博主通常已掌握产品特点，却需要进一步判断“为谁写、解决什么困扰、怎样组织使用场景、哪些说法有依据”。一次推广内容还涉及资料整理、改稿、审核、排版和确认；持续运营需要维护账号定位和历史记录。材料分散、同一问题反复修改及版本混淆，是本项目选择处理的具体工作问题。

研发目标是将资料、语言模型和人工决定组织成可恢复、可核对的工作流程，让用户从产品事实获得可编辑稿件，再将读者疑问转为有依据的局部修改。项目不预设所有用户的市场需求已经得到验证，不编造行业规模、付费意愿或效率提升比例。已有三位读者反馈和用户操作记录用于发现问题，样本边界见第五章。

### 1.2 产品定位与差异化目标

有迹属于AI赋能的内容创作与运营软件，以本地网页工作台使用，面向小红书、抖音内容的准备与复盘。核心输出是文案、中文图卡、分镜字幕和无声图文视频；真实平台发布由用户自行完成。用户可以采用四角色创作，也可以按需进行读者检查，并选择修改后回到创作复审。

差异化目标是证据和稿件版本一致、局部修改可定位、人工确认可追踪、后台失败可恢复。当前能验证的是这些软件机制；算法精度、同任务效率、成交或传播优势没有充分实验支持。项目不承诺爆款，不把模拟受众或人工填报当作真实平台核验。

### 2.3 创新应用与可比较边界

第一，阅读与事实核验分离。作者确认固定问题后，阅读阶段判断正文能否回答，核验阶段再检查资料是否支持；材料中有答案不能掩盖正文未讲清。模型输出必须覆盖同一问题集合，并定位当前稿件和对应来源。修改后复查同一问题，不通过删除难题提高结果。

第二，局部修复接回创作复审。补丁绑定问题、报告、原文位置和资料引用；用户选择采用后形成新检查稿。回写创作时核验来源任务、账号、所有权、稿件引用/hash和版本，事务内新增人工稿件与支持材料快照，保留原稿和历史审核，清除当前确认。用户随后主动启动复审，检查通过不等于创作审核通过。

第三，批准、执行与费用共同约束。旧稿及过期审核不能用于新确认；幂等操作不重复新增产物，迟到结果不能覆盖取消或新版本。未知付费用量保留预留并阻断自动重发；已有成功节点与已收到响应可按校验规则复用。

这些是项目实现的软件机制组合和场景适配，哈希、引用核对、幂等及相似度方法本身不是首创算法。与单次聊天、普通全稿审改相比，本项目增加可复核的中间状态和人工选择点；这属于流程差异描述，没有充分证据证明总体质量、精度或效率更优。

## 三 功能设计与实现

### 3.1 核心功能及AI实现

[[workflow]]

| 核心功能 | 输入、AI环节及输出 |
| --- | --- |
| 四角色创作 | 账号定位、用户目标、共享原文快照进入受众/研究分析；content生成策略、提纲、标题和正文；reviewer形成当前版问题及处理状态。 |

| 可选读者检查 | 当前稿件、作者确认问题及支持材料进入分离的阅读/核验阶段；输出逐项理解与依据状态，材料不足保留未知。 |
| 局部修复与回写 | AI提出有来源的可阅读补丁，程序校验位置、引用与版本，用户选择采用；回写原创作的新稿和支持材料，随后主动复审。 |
| 排版与导出 | 从准确确认版制作Pillow或HTML模板图卡、无声MP4和字幕；预览/导出绑定稿件与设计hash。确定性导出无需语言模型。 |
| 选题参考与运营复盘 | 参考匹配受账号、指标窗口及历史观测时点约束；可选SKAPP不可用时不制造预测值。手工指标支持免费描述性分析；真实AI解读另需主动授权。 |

四角色不自主无边界联网。公开搜索和读取由用户主动发起，搜索摘要与已读原文分开；页面来源、许可和真实受众历史仍需用户核实。旧材料被删除或更正时，新检查回写采用当前支持材料，不继续把旧事实送入新复审。

### 3.2 辅助功能及协同关系

账号以稳定account_id关联，网站用户与社媒账号分离，owner/account_id控制数据范围。会话、CSRF、操作来源、版本及幂等共同约束读写，恢复码仅保存哈希。资料支持UTF-8文本、Markdown、文本型PDF、DOCX，保存原文、页码或段落位置和版本；BM25检索的证据快照供各角色共用。

资料停用不抹除旧任务证据，人工编辑不覆盖旧稿。运营记录及经验区分模拟与真实填报，同平台同账号才可复用；指标纠正或经验撤销会使依赖分析、经验和计划失效。缺失指标不填零，读者需求不直接当作产品事实。当前没有账号删除HTTP契约；资料删除通过停用排除新检索，安装包验收没有把它写成全面数据擦除。

### 3.3 扩展性设计

新供应商需实现Calls适配器及同一响应、审计、用量和失败契约，不宣称任意模型即插即用。检索升级应先建立资料查询样本，再比较关键词与混合检索。SKAPP/ChineseCLIP模型包、模型授权与真实数据预测质量单独验收，不因语言模型或媒体模块可用而宣布其通过。

平台OAuth、发布与指标回流需获得适用账号/API授权；公网部署需另做HTTPS、权限、备份和外部设备验收。OCR、AI绘图、配音和高并发优化按需求评估，未列为当前已实现交付。

### 4.4 本地安装与云端部署

macOS原生包内嵌Python运行时及已验收媒体依赖，用户解压应用后启动可执行程序，通过自动打开的本机网页使用。新SQLite资料位于独立可写用户目录，启动器不读开发项目.env，不复制旧数据库；API和Worker的任一服务失败会停止另一服务并保留脱敏日志。真实AI需要受控私有配置和网络，离线导出测试不需收费模型。

### 5.2 市场分析与竞争维度

本项目选择“小品牌已有产品信息、需要自然推广表达”的细分场景，不假设所有博主都是目标用户。通用生成、编辑排版、运营管理及审核协作可从资料依据、版本一致性、局部修改、采用控制、费用记录和导出路径比较；这是一套比较指标，不是对所有竞品能力的调查结论。

目前没有可信市场规模、商业收入、用户付费意愿或获客成本数据，不填虚构数字。既有读者来自单个校园选购案例，不足以推断目标品牌用户的代表性需求。商业可行性应基于实际用户使用中的资料准备负担、修改量、完成率及愿意持续使用的原因，再确定收费模式和推广渠道。

### 5.3 成果总结及贡献边界

当前成果是四角色创作、资料证据与版本保存、审改/人工决定、可选来源约束检查与回写、可恢复后台，以及已有Mac包本机HTTP和媒体依赖验收。工程上解决了“检查结果与创作分离”“旧资料沿用”“稿件和审核版本混用”等问题。

大模型、SKAPP网络、ChineseCLIP、BM25、LangGraph、FastAPI及开源模板均按第三方来源标注。项目自行实现输入组织、账号适配、定位引用、预算台账、事务守卫及人机流程；未训练新基础模型，不声称新算法原创或已测得精度提升。现有证据不足以证明减少多少人工时间、提升多少成交率或优于普通改稿。

官方评分维度为创新性20分、技术实现20分、功能完整性20分、方案完整性20分、应用价值15分和总结与展望5分；这用于整理证据，不是预计得分或获奖保证。
