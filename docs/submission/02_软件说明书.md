# 有迹软件说明书

## 2026-11-02 当前使用增补

新建任务默认开启创作规划与结构适配，关键问题询问默认关闭，可在高级设置选择。问题出现后可补料生成新快照，也可跳过后继续，缺口不会自动成为事实。小红书标题不超过20字符，合法备选不足五个时如实展示，不截断原句。当前实现见[修订说明](../evidence/sprint-20261102/ALGORITHM_REVISION.md)，实测见[验收报告](../evidence/sprint-20261102/FINAL_REPORT.md)。

本说明书面向使用者与部署人员，介绍从账号设置到内容导出的操作方法，以及本机服务的安装与恢复。软件当前提供网页操作界面，正式入口为 FastAPI 服务；源码部署默认本机地址 `http://127.0.0.1:8765/#overview`，Windows 运行包由启动器自动选择端口（优先 8890）并打开浏览器。

## 一、软件用途和使用条件

有迹用于小红书内容稿和抖音口播、分镜脚本的辅助创作，并支持账号历史与运营复盘。用户需要提供自己的需求和合法使用的材料，对最终稿件负责。发布动作、成片拍摄与平台合规由创作者按平台规则完成；软件负责稿件与脚本的文本、版本与依据。

网站身份用于登录和数据隔离；页面中的社媒账号档案用于创作定位，不等于已获得小红书或抖音授权。免费模拟模式可以检查操作流程，但固定模板内容不能证明真实模型质量。真实模式调用第三方模型，会产生费用，需先配置并确认可用预算。

## 二、登录与账号准备

1. 打开网站并注册。新密码为8至20个字符，同时包含英文大写和小写字母。妥善保存注册时的一次性恢复码，不把恢复码放入稿件或共享材料。

2. 登录后建立社媒账号档案，选择目标平台，填写定位、受众、表达偏好和禁用表达。软件使用稳定 account_id 关联记录，修改昵称不会生成另一个账号身份。

3. 按需录入历史作品、同类账号公开观察及指标。只能填写有依据的信息，缺失项保留未知。演示数据与人工录入数据分开，模拟经验不进入真实 AI 上下文。

4. 忘记密码时使用网站恢复码重设，旧会话将被撤销。当前没有短信或邮件找回服务；旧 Demo 恢复码不等同于网站恢复码。

## 三、资料准备

在资料库选择账号，粘贴文本或上传 UTF-8 TXT、Markdown、文本型 PDF、DOCX。单份文件最多 3,000,000 字节、PDF 最多 50 页、正文最多 100,000 字符；文本型 PDF 与 DOCX 可直接解析入正文。保存前可预览、校对、返回修改，确认后才入库；保存后可查看资料版本与原文位置。

导入时需选择**资料用途**，它决定资料进入哪一组检索：

| 用途 | 进入的检索组 | 用于 |
| --- | --- | --- |
| 写作材料 / 待核验事实 | `facts` 事实组 | 可被引用、需注明来源的规格与结论 |
| 写法参考 | `examples` 样例组 | 只学结构与表达，**不能被当作事实引用** |
| 通用方法 | `methods` 方法组 | 跨领域的写作方法 |

同一来源可按不同用途分别保存。检索仅使用当前账号有效资料；更新会创建新版本；移出资料库后新任务不再检索该资料，但旧版本与任务证据仍保留。彻底删除个人数据按部署方策略执行：本机版可直接删除 data 目录，内网版由管理员按数据库备份与留存策略处理。

## 四、从需求到确认稿件

### （一）创建与执行

选择账号和目标平台，填写选题、目标读者、风格及素材。需要使用资料库时勾选检索，检查取回的来源是否与需求相关。软件将相关原文、账号上下文和路由策略保存为任务快照。

选择模拟或真实 AI 模式后，提交“后台运行到人工处理”。观察受众分析、素材研究和内容阶段产物。后台不会因为浏览器关闭而停止，但数据库与 Worker 必须保持运行。进度展示的是已保存的执行事件，不是质量评分。

### （二）补料和返修

资料不足时根据问题补充事实，避免要求模型编造亲历经历或统计。审核提出修改意见后，可在当前额度内继续自动返修，或手动编辑。错误、超时和用量未知不会自动无限重试；达到次数或预算限制时应检查原因。

### （三）版本确认与导出

选择其他候选标题或修改正文都会产生新版本。阅读版本差异后重新审核，只有当前有效审核对应的稿件可以确认。确认后可下载 **Markdown**，或下载**可编辑的 Word 确认稿（.docx）**，后者包含标题、正文、互动引导与标签，并标注确认方式。确认意味着用户接受该版本，不意味着平台已发布或平台审核通过。

若稿件未通过 AI 审核但用户决定采用，文档中会明确标注「人工采用、未通过 AI 审核」，不伪装成审核通过。

抖音输出为口播与分镜脚本，拍摄、剪辑、音乐与素材授权由使用者按平台规则完成。

### （四）连接小红书（可选）

在「连接与设置 → 账号数据连接」中展开「连接小红书」，点击「扫码登录小红书」，用本人的小红书账号扫码，再点击「完成连接」。系统会核对账号身份后才写入绑定；不同账号不会互相覆盖。

未启动本机连接器或登录已失效时，页面会给出可操作提示，不会把失败显示成「没有数据」。连接器为只读，仅读取本人公开笔记与已保存评论；**不发布、不点赞、不评论、不关注**。连接器以本机可选组件形式提供：已部署并完成扫码授权时按上述流程读取；未部署时该入口给出连接指引，用户仍可用自有文档或粘贴文本完成全部创作流程。

## 五、发布记录与持续运营

用户在社媒平台手动发布后，可以回填链接和时间。MANUAL_REPORTED 表示用户报告的记录，没有平台独立核实；SIMULATED 只表示演练。

在24小时、72小时或7天等观察窗口录入指标。阅读或播放分母缺失、为零，或组成指标不完整时，比例保持未知。分析比较同账号、同平台、同内容形式、同流量类型、同来源和同窗口的历史记录。

复盘分为观察、假设和下次实验。阅读限制说明后决定是否采纳经验；有效经验可供后续创作和周计划使用。修正指标、分类或撤销经验后，相关计划可能变为需要重新检查，应重新生成并确认。该过程不是大模型在线训练，也不证明因果效果。

## 六、运行环境与本机部署

### （一）环境与依赖

本机测试环境为 Apple silicon、Python 3.12.14、PostgreSQL 18.6；Windows 运行包内置独立 Python 运行时，不依赖系统 Python 与数据库服务。完整依赖锁定在 requirements.txt。

在项目根目录创建虚拟环境并安装依赖，使用管理员预先创建的项目专用数据库。以下不包含真实密钥或密码：

```bash
python3 -m venv runtime/venv
runtime/venv/bin/pip install -r requirements.txt
```

在本机配置文件 .env 中设置数据库与来源地址。数据库用户名和凭据由部署人员按本机权限配置；下方示例使用本机数据库身份，不代表通用免密码部署。

```dotenv
DATABASE_URL=postgresql:///youji_operations
PUBLIC_ORIGIN=http://127.0.0.1:8765
```

真实模式另设置 DEEPSEEK_API_KEY。不得把真实配置文件、Cookie、恢复码或数据库备份放入参赛代码包。模拟模式无需真实模型密钥。

### （二）启动两个进程

在两个终端分别执行，下方均在项目根目录运行：

```bash
runtime/venv/bin/python -m backend.api --port 8765
runtime/venv/bin/python -m backend.worker
```

API 与 Worker 必须共享同一个 DATABASE_URL 和模型配置。打开 http://127.0.0.1:8765/，地址必须与 PUBLIC_ORIGIN 一致。检查 /health 返回的版本与数据库状态，再通过模拟任务验证界面、后台执行及人工确认。

### （三）数据升级与备份

新增核心表通过 backend/migrations.py 顺序迁移并检查校验和。更新前停止写入并备份 PostgreSQL；不要修改已应用迁移或删除迁移记录强行降级。原 SQLite 数据迁移仅适用于已确认的旧环境，详细迁移命令见 docs/DEPLOYMENT.md；新安装无须导入旧用户数据。

## 七、故障处理与验收

| 现象 | 处理方式 |
| --- | --- |
| 无法连接网站 | 确认 API 启动、端口和地址正确；本机优先使用127.0.0.1 |
| 已排队但不执行 | 确认 Worker 与数据库运行，且两个进程使用同一配置 |
| 会话过期或写入被拒绝 | 刷新后重新登录，核对访问地址；不要绕过CSRF或来源检查 |
| 稿件版本冲突 | 重新载入任务并检查最新稿件，修改后再次审核 |
| 资料检索无结果 | 检查账号、资料有效状态与「资料用途」是否匹配；检查候选是否为本账号有效版本。若未提供本地向量模型，检索按词项方式执行，并在界面与快照中标注实际引擎 |
| 检索结果不是语义结果 | 界面与任务快照会标注实际引擎。显示 `filtered-bm25-zh-bigram-v1` 时表示本次为词项检索，不是语义检索 |
| 资料导入后仍检索不到 | 确认用途选择：写法参考只进入样例组，不会被当作事实引用；事实资料需与主题相关并通过型号校验 |
| 无法连接小红书 | 确认本机连接器已启动且登录有效；未部署连接器时按页面指引改用自有文档或粘贴文本 |
| 网页读取失败 | 检查公开可访问性或改为手工提供合法原文；不将摘要当正文 |
| 模型输出错误或预算不足 | 查看失败阶段与用量，修正输入或配置后按状态允许的方式处理 |
| 模型用量未知 | 先人工核对供应商账单，不自动重发；当前无自动对账放行入口 |

### （一）恢复说明

Worker 重启后可在旧租约过期后领取任务，生产租约为30秒。已保存节点及已接收响应可复用；取消后迟到结果不能提交新稿件。电脑关闭时任务暂停，需要重新启动数据库、API与Worker。持久化不等于服务永不中断。

### （二）工程复验

使用独立测试 schema，运行以下命令。未配置 TEST_DATABASE_URL 导致的数据库测试跳过不能算完整通过。

```bash
TEST_DATABASE_URL=postgresql:///youji_operations \
PYTHONDONTWRITEBYTECODE=1 runtime/venv/bin/python \
  -m unittest discover -s tests -v
```

交付基线在 SQLite 路径上的实测结果为 **1189 项：955 通过、234 条件跳过、0 失败 0 错误**；前端 `node --test` **256 项全部通过**。跳过项构成与结论边界以配套测试报告为准，不把跳过计为通过。

前端检查使用 `node --check` 或 `node --test tests/*.test.js`。角色卡生成结果应与已有文件一致；同时执行 `git diff --check`。测试使用替身，不产生真实模型费用。

评测框架可离线自检，不调用模型、不产生费用：

```bash
runtime/venv/bin/python scripts/evaluation_bench.py --self-check
```

### （三）部署形态与访问方式

本版本以两种形态交付：Windows 免安装运行包（推荐，双击启动器即在本机拉起服务）与源码部署（API + Worker 双进程）。评审复现通过任一种形态在本机启动，地址为 `http://127.0.0.1:端口`，端口由启动器按可用性选择。

如需异地演示，按下述清单部署后再开放访问：HTTPS 终结、不少于 16 位的注册邀请码、最小权限数据库身份、进程托管与自动重启、日志与告警、备份恢复演练、外部设备连通性验证。开放前用 `/health` 核对版本与数据库状态，并用一次模拟任务验证界面、后台执行与人工确认全链路。
