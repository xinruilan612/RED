## 内容风洞改稿闭环的通用性修复（2026-10-24）

用户指出上一轮只改了文案，没有让“换一份稿件或换一组问题”同样成立。本轮按系统行为修复，不重写任何稿件：

- **改稿面板只看当前有效报告**：`wtPatchForm` 以前取“最后一次报告”，稿子改过以后仍会列出旧结论，点下去才被后端以“当前稿件和条件没有有效检查报告”拒绝。现在使用 `wtReport()` 并先过 `wtReportIsCurrent()`；报告过期时直接显示“按原条件复查当前版本”，不再给出可点击的过期问题。
- **只列未通过项**：勾选列表过滤 `status==='pass'`，避免用户勾到已讲清的问题再被 `propose_patch` 拒绝；全部通过时保留“这一版没有需要改的问题”的空状态。
- **模拟模式不再提供做不到的按钮**：模拟阶段 `simulate(run,'wt_patch')` 恒返回空补丁，后端不会编造可采用的修复。面板现在禁用勾选与按钮，并说明需要切到真实 AI；手工改正文仍走“保存新版本→复查”。
- **空提案不再显示“采用”**：`wtPatch` 的 `applicable` 增加 `items.length` 条件，空提案只留审计记录与“材料不足以支撑修改”的说明。
- **修改提案区标题按模式显示**，不再固定写“当前为模拟修改提案”。
- **单换行稿件也有局部修改目标**：`edit_spans` 仍以空行分段；当分段少于 3 个时回退到按行切分（最多 60 个目标），否则小红书常见的单换行正文只能“整篇替换”。空行分段的稿件行为不变（100 段仍为 121 个目标）。
- **CRLF 稿件不再带回车进目标**：分隔符改为 `\r?\n` 识别；从 Word/Windows 粘贴的稿件，替换目标不再以 `\r` 结尾。

验证：前端 `node --test tests/*.test.js` 275 项通过（新增 `frontend_windtunnel_patch_view.test.js` 覆盖“只列未通过／过期报告／模拟禁用／空提案”）；`tests.test_windtunnel_domain` 34 项通过。新增用例按“换一份就重来”组织：6 种稿件形态（单行／单换行／空行分段／CRLF／重复段落／表情符号）逐一跑完 提案→采用→新版本文本校验，另加“同时选多个未通过问题”“采用后旧提案失效、复查后新稿仍可改”。`tests.test_windtunnel_runtime` 与 `tests.test_windtunnel_api` 在本机仍有 3+6 与 3 项环境错误（检查点子进程与沙箱），改动前后一致，未新增失败。本轮未调用真实模型，未改数据库结构。

## 引文校验不再整段中止（2026-10-29）

真实任务 `1acd5e57-8711-4d0d-ac92-3ef83a923cbd` 的 audience 调用被 `模型引用无法匹配原始素材` 拒绝，任务停在 brief。根因是模型把原文“回到家中”写成“回到家里”，逐字校验整段失败；同批历史失败共 46 条响应，其中 review 15、audience 24、research 7。

修复分三层，均在 `backend/citation_ids.py`，不改变存储引文必须逐字来自原文这一事实：布局（空白、换行、全半角、引号）归一化；整行重排（每个字段行各自逐字）拆成多条；非数字近似复述（数字与英文型号必须完全一致，相似度 ≥0.92、长度 ≥12）定位回原文并记录 `quote_near_match`（保留 from/similarity/to 审计）。仍无法定位的条目不再让整个阶段失败：audience 剔除该条并在 basis 写明条数，research 剔除并在 gaps 记录、全部失效时置 core_gap=true；把样例、写法或评论当事实引用仍判 `MODEL_OUTPUT_INVALID`（`inadmissible_fact_sources`），review 仍严格逐字并在失败时走既有保守交接。
