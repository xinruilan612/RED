# 本地看图交互试用

## 使用

确认稿 → 选择整套模板 → 预览图卡 → 点左侧正文页 → 在“看图调整（本地 AI 试用）”填写意见 → 生成提案 → 看前后对比 → 采用 → 下载全部成品包。

试用意见：`这一页文字太挤，请拆成两页，保留全部文字和产品图片。`
另一项：`移除这一页的产品图片，保留文字。`

目前只支持这两种操作。改写正文仍在改稿区进行。模型先观察真实 PNG 并给出操作与理由；程序校验并执行排版，不让模型任意修改 HTML 或执行代码。拆页保留逐字内容，照片只保留在拆分后的第一页。取消提案不会替换现有预览，采用后导出才使用新布局。

## 开源运行方式

- 本机推理服务：[Ollama](https://github.com/ollama/ollama)，MIT。
- 图像理解模型：[Qwen3-VL](https://github.com/QwenLM/Qwen3-VL)，Apache-2.0；使用 [qwen3-vl:4b](https://ollama.com/library/qwen3-vl:4b)。
- 图卡仍由现有 MIT HTML/CSS 模板渲染；不是让模型生成产品照片。

安装并启动 Ollama 后执行 `ollama pull qwen3-vl:4b`，约需 3.3 GB 下载空间。API 进程与 Ollama 必须位于同一台机器，目前固定访问 `http://127.0.0.1:11434/api/chat`。适用于当前单机试用，尚未设计公网多用户推理部署。

没有云端回退，不使用 DeepSeek 密钥；没有模型 API 费用，但占用本机内存和计算资源。首次载入可能较慢。连接或推理失败显示原因、保留原图，不自动重试。文字和图片中的指令均视作素材。

## 数据与边界

核心迁移 10 新增 `local_media_calls`，独立记录本地图像调用的模型、图片与输入哈希、反馈、结果和实际 token；不混入付费创作台账。图片本身不写入调用日志。每个用户同时只允许一次本地分析。

服务端重新生成所选稿件对应的 PNG，核对稿件、设计哈希、登录权限和 CSRF；推理后再次检查确认稿。提案先只在浏览器显示，明确采用后才成为下载参数。已确认文案和原稿历史不变。当前浏览器保存排版选择，自定义上传照片仍为临时文件；刷新后的行为见页面提示。

## 验证

回归测试覆盖实际 PNG 传入模型接口、拒绝重定向和代理转发、审计与并发、权限与过期预览、拆页文字完整、图片索引、预览导出一致、提案采用/取消与状态竞争。替身测试不能证明视觉模型质量。

### 2026-10-09 本机实测

完整后端回归 967 项、0 跳过；视觉返回兼容修复后补跑 23 项相关测试，全部通过。前端 296 项通过，脚本语法、角色卡同步、git diff --check 通过。

本机 qwen3-vl:4b，模型摘要 `1343d82ebee38e26a4dd6b0180b915eb91550184e67c505dea97509571c8f683`，约 3.30 GB。真实模型收到罗技图卡 PNG，识别照片和文字并返回 split；实际 3→4 页，正文逐字校验不变。另以 remove_photo 实测，页数不变、仅所选页图片移除，正文和其他页保留。两项含排版与导出各约12秒，仅为本机样本，不承诺固定耗时。

Chrome 完成“提意见→真实模型→前后对比→采用→下载”，实际下载的4张PNG与验证预览逐字节一致，caption.txt不变。产物与记录位于本机 output/local-vision-trial-20261009/ 和 output/local-vision-remove-trial-20261009/，不提交用户运行数据。

首轮模型返回字段兼容失败，已如实记录失败调用。依据 [Ollama 已知问题](https://github.com/ollama/ollama/issues/14798)，仅在content为空、另一个字段全文是完整且符合三字段契约的JSON时接受，记录structured_source。不会从自由推理中抽取指令，不保存或展示自由推理，也不自动重试。
