5.5. Dictionaries

Another useful data type built into Python is the dictionary (see
Mapping Types — dict). Dictionaries are sometimes found in other languages as
“associative memories” or “associative arrays”.  Unlike sequences, which are
indexed by a range of numbers, dictionaries are indexed by keys, which can be
any immutable type; strings and numbers can always be keys.  Tuples can be used
as keys if they contain only strings, numbers, or tuples; if a tuple contains
any mutable object either directly or indirectly, it cannot be used as a key.
You can’t use lists as keys, since lists can be modified in place using index
assignments, slice assignments, or methods like append() and
extend().

It is best to think of a dictionary as a set of key: value pairs,
with the requirement that the keys are unique (within one dictionary). A pair of
braces creates an empty dictionary: {}. Placing a comma-separated list of
key:value pairs within the braces adds initial key:value pairs to the
dictionary; this is also the way dictionaries are written on output.

The main operations on a dictionary are storing a value with some key and
extracting the value given the key.  It is also possible to delete a key:value
pair with del. If you store using a key that is already in use, the old
value associated with that key is forgotten.  It is an error to extract a value
using a non-existent key.

Performing list(d) on a dictionary returns a list of all the keys
used in the dictionary, in insertion order (if you want it sorted, just use
sorted(d) instead). To check whether a single key is in the
dictionary, use the in keyword.

Here is a small example using a dictionary:

>>> tel = {'jack': 4098, 'sape': 4139}
>>> tel['guido'] = 4127
>>> tel
{'jack': 4098, 'sape': 4139, 'guido': 4127}
>>> tel['jack']
4098
>>> del tel['sape']
>>> tel['irv'] = 4127
>>> tel
{'jack': 4098, 'guido': 4127, 'irv': 4127}
>>> list(tel)
['jack', 'guido', 'irv']
>>> sorted(tel)
['guido', 'irv', 'jack']
>>> 'guido' in tel
True
>>> 'jack' not in tel
False

The dict() constructor builds dictionaries directly from sequences of
key-value pairs:

>>> dict([('sape', 4139), ('guido', 4127), ('jack', 4098)])
{'sape': 4139, 'guido': 4127, 'jack': 4098}

In addition, dict comprehensions can be used to create dictionaries from
arbitrary key and value expressions:

>>> {x: x**2 for x in (2, 4, 6)}
{2: 4, 4: 16, 6: 36}

When the keys are simple strings, it is sometimes easier to specify pairs using
keyword arguments:

>>> dict(sape=4139, guido=4127, jack=4098)
{'sape': 4139, 'guido': 4127, 'jack': 4098}

If you start from
tel = {'jack': 4098, 'sape': 4139}
and then add guido: 4127, change jack to 5000, delete sape,
and add irv: 4127, the corresponding final dictionary is
{'jack': 5000, 'guido': 4127, 'irv': 4127}.
The manuscript shows the same pattern when it starts with
tel = {'jack': 4098, 'sape': 4139}, adds tel['guido'] = 4127,
deletes del tel['sape'], and adds tel['irv'] = 4127, giving
{'jack': 4098, 'guido': 4127, 'irv': 4127}.
The manuscript also states that if you store using a key that is already in use,
the old value associated with that key is forgotten; that statement covers the
change to jack: 5000.

For this final dictionary, list(tel) returns
['jack', 'guido', 'irv']
and sorted(tel) returns
['guido', 'irv', 'jack'].
The manuscript gives the same two results for its own dictionary:
list(tel) returns ['jack', 'guido', 'irv'], and sorted(tel)
returns ['guido', 'irv', 'jack']. The unsorted list is in insertion order,
because the manuscript says list(d) returns all keys “in insertion order”;
sorted(d) instead gives sorted order.

To check whether guido exists in the dictionary, write
'guido' in tel
and the result is True. The manuscript shows the expression
'guido' in tel with result True, and explains that the in
keyword checks whether a single key is in the dictionary.

Reading sape after it has been deleted is an error. The manuscript says:
“It is an error to extract a value using a non-existent key.” It also shows
that sape was removed by del tel['sape'] and is absent from the later
list(tel) and dictionary output, so a later read such as tel['sape']
would be extracting a value using a non-existent key. The manuscript does not
print the exact exception type for that error.

Using a list as a key is not possible. The manuscript says, “You can’t use
lists as keys, since lists can be modified in place using index assignments,
slice assignments, or methods like append() and extend().” Using a tuple that
contains a list as a key is also not possible, because the manuscript says that
if a tuple contains any mutable object either directly or indirectly, it cannot
be used as a key. A tuple is usable as a key only if it contains only strings,
numbers, or tuples. Thus a list is mutable and unusable as a key, and a tuple
containing a list is likewise unusable as a key.
