# 风洞正文修复与完整复测

2026-10-07。原 v1 结果保留在 [历史报告](../REPORT.md)。本次修复了占位改稿、字符定位和引文格式问题，并在用户原有累计 5 元授权内完成 7 篇 × 2 组的真实模型回归。它们是重复使用的公开教程，不是新的隐藏留出集。

## 产品改变

风洞改稿必须针对作者选中的未通过问题，给出有材料引用、可直接阅读的正文；禁止把“待补充/待核实”或原问题追加当作修复。没有支持材料就返回空补丁并保留未解决项。模型选择段落、材料证据和读稿摘录的确定性 ID，程序还原原文与位置，拒绝过期 ID、错误来源、内部重叠和无依据修改。ID 存在不表示引用在语义上正确，仍需核验。

本轮把五点复合作者任务拆成五条条件，分别读稿、核验，只向改稿阶段传选中的问题；修复后用原条件复查，检查新问题。允许从正文讲明的规则作直接推导，避免要求正文逐字含每个定制示例；禁止拿模型自己的知识填缺口。

## 7 篇完整回归

普通审稿和风洞均为真实 DeepSeek Flash 非思考调用，通过 Service/Worker 执行。14/14 流程完成，新增 31 次真实请求；风洞七稿最终各 5 条条件全部通过。S04 采用 1 个实质补丁，其他六稿保持原样。机器复查通过不等于独立读者效果，也不能把未改动的稿件算作提升。

S04 增加了“筛去负数再翻倍”的具体表达式 `[x*2 for x in vec if x >= 0]` 及 `[0, 4, 8]`，同时给出展平、元组括号、循环顺序和变量作用域解释。原 v1 只是追加“待补充并核实”问题，当前正文提供了可执行的小抄。逐稿输出、原始模型响应、失败和冻结代码均保留。

## 三篇缺口控制：变化必须解决具体任务

测试前冻结了 S06 文件读写、S07 JSON、S10 命令行解析的人工删节稿，保留各自完整官方材料。原稿只剩两句概述，明确标注“人为删节缺口控制，非真实创作者”，不能算真实博主稿件或自然发生的缺陷。任务及五点标准在修改前锁定，参考答案不传给编辑模型。

| 控制 | 实际修复 | 采用补丁 | 复查 |
| --- | --- | ---: | --- |
| 文件读写 | 追加模式/UTF-8、with关闭、EOF/空行、逐行读取、二进制JPEG限制 | 1 | 原条件通过，无新增问题 |
| JSON | 序列化/反序列化、dumps/dump/load、UTF-8、pickle风险与类实例限制 | 2 | 原条件通过，无新增问题 |
| 命令行解析 | 参数定义、parse_args、Namespace、帮助/错误行为 | 1 | 原条件通过，无新增问题 |

JSON 初次模型已返回实质正文，却被程序误判为“修改范围重叠”：段落替换的终点与紧随其后的插入点相等。已修正半开区间判断与采用顺序，允许相邻修改，仍拒绝区间内部插入、真实重叠和同点多次插入。新旧输入顺序及单项/全部采用均有回归覆盖。

保留 [原失败结果](evidence/controls/cases/S07/windtunnel/result.json)。在隔离数据库备份内，严格重新校验已收到且用量已知的原响应，复用同一 call_id 和原始响应，不重复请求模型；随后只有两次新复查调用。见 [恢复审计](evidence/boundary-recovery/recovery-audit.json)、[恢复结果](evidence/boundary-recovery/cases/S07/windtunnel/result.json)。无效缓存依然拒绝，未知响应不重发。其他两稿沿用原结果，未重新执行；新目录中的复制不表示新增调用。

这三例证明流程能够把有材料依据的任务缺口变成正文并复查，不能仅凭模型自检证明读者效果，更不能证明优于普通 AI 改稿。普通审稿也真实执行三次，输出全部保留，但下面的代理读稿比较是“原删节稿 vs 风洞最终稿”，不是普通审稿 vs 风洞。

## 怎样才有提升

先定义读者要完成的任务，例如“新手能保存并恢复 JSON，知道如何避开不可信 pickle”，拆成可核对的步骤、例子、前提和失败处理。只补原稿缺少、资料能支持的部分，优先把抽象描述换成可操作示例和明确结果。资料不足就保留缺口，不能靠追加问题或猜答案凑通过；成熟稿不必强行改写。

修改后用相同任务检查“原来找不到的答案是否能在正文找到、是否引入错误”。再用未见另一版本的读者验证任务完成，保留原回答及定位证据。当前控制结果最多支持缺口补齐能力；要主张真实创作者收益、优于普通改稿或传播效果，还需要代表性的未完成草稿、新冻结样本、同信息预算对照与真实用户/平台数据。
