# 内容风洞演示脚本

使用 [团队自建材料](DEMO_MATERIAL.md)，画面保留“模拟”与“团队自建”标识。脚本不是已录制视频，预计时长随实际操作调整；参赛成片应核对 3—5 分钟等适用提交要求。

| 顺序 | 画面与操作 | 需要看见的证据 |
| --- | --- | --- |
| 1 | 登录普通演示账号，进入内容风洞；粘贴原稿与独立材料 | 当前账号、模拟模式和材料来源清楚；不展示密码或恢复码 |
| 2 | 生成或填写候选问题，确认三张作者设定卡 | 条件来源类型、适用范围和确认版本；不是虚构真人评论 |
| 3 | 提交后台检查 | 网页显示任务状态；阅读检查依据稿件，资料核实单独执行 |
| 4 | 打开菜单/编码问题与“离线可用”问题 | 模拟保守显示未讲清及“不核实事实”；可旁列原稿、材料，不声称已自动定位遗漏 |
| 5 | 查看局部修改差异，由作者采用 | 旧稿保留；修改范围可核对，没有默默覆盖未采用稿件 |
| 6 | 用相同条件复查 | 稿件版本变化、条件版本保持；不能删掉困难条件获得全通过 |
| 7 | 刷新页面并回到该任务，导出报告 | 保存状态与相同版本可找回；导出保留模拟/来源/限制说明 |
| 8 | 展示空白研究方案及待办 | 说明 3 篇探索 + 7 篇留出、42 次阅读尚未执行；不显示虚构提升率 |

补充工程展示可另录：停止 Worker 后提交任务，证明任务排队；重启 Worker 后观察恢复。服务重启及故障恢复结果只有实际完成并记录后才能写成“验证通过”。如果使用历史报告回放，标明回放，不当成现场实时运行。

建议讲述：“稿件写了点击导出，却没说具体菜单、格式和编码。我们把作者确认的问题保存成固定条件，分别安排阅读检查和资料核实，修改后仍用同一组条件检查。当前免费模拟只展示流程和版本约束，实际自动检查效果等待真实模型与读者对照。”
