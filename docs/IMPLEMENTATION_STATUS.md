## 已能使用

- 填写创作需求、目标读者、风格和素材，创建任务。
- 同时执行受众/素材模拟分析；逐步查看策略、提纲、开头、标题、正文。
- 查看每个角色的输入、输出、实际阶段耗时和运行记录。
- 在资料不足时可视化补料；审核发现问题时选择自动返修或手动编辑。
- 改稿保存新版本、比较旧稿与新稿、再次审核、人工确认准确版本。
- 下载确认后的 Markdown；同一浏览器刷新保留历史。
- 后端提供状态校验、持久化、版本冲突拒绝、命令幂等、会话隔离、CSRF/Origin/Host 检查；预算基础规则仍由原领域层测试验证。

## 技术边界

新增 backend/demo.py（四角色模拟及逐阶段执行）、backend/web.py（仅回环 HTTP 适配）和 frontend/（原生页面）。这是零第三方依赖的可替换演示适配层，不改变后续 FastAPI/Next.js/PostgreSQL/队列的产品部署计划。创建的 Run 增加 context/artifacts/node_runs/reviews，旧本地域记录仍可由默认字段读取；网页仅创建和操作模拟任务。

## v0.6 资料库与真实来源（2026-09-21）

在现有目录新增 knowledge.py、sources.py、document_parser.py 与 knowledge.js。资料按 owner/account_id 隔离，支持粘贴文本、UTF-8 TXT/Markdown、文本型 PDF（3 MB / 50 页 / 10万字符）；PDF 在限时子进程解析，保留页码、位置、版本、原文件和指纹。扫描件 OCR 尚未实现。更新采用 expected_version，原版本不覆盖；移出资料库后新检索排除，已有任务快照保留审计。

RAG 首版是中文双字词及英文词的 BM25 原文检索，不是语义向量检索；未接 embedding 服务或 pgvector 索引。创建任务时可选检索同账号资料，最多4个片段、每段400字符，服务器生成 source_id 并冻结进入上下文。四角色读取同一快照，研究 facts 与审核 claim_map 逐字匹配。不会把检索相关度解释为事实可信度或传播概率。

搜索为用户手动发起的维基百科公开 API（背景知识）或 Bing 公开 RSS（网页实验接入），无搜索 Key、无收费模型请求；摘要明确 body_read=false，没有可靠发布时间则 null。公开正文可读取并入库，保留 fetched_at 与页面声明时间。没有自动订阅热榜或平台内部数据。任意网页抓取校验公开 IP、逐跳重定向与固定地址连接，拒绝内网、文件协议、凭证 URL、自定义端口，限制读取体积和时间。固定搜索服务单独使用标准 HTTPS 客户端，固定主机与路径、禁止重定向。

真实网络实测：搜索成功返回公开结果，也出现超时和不相关结果；通过网站 API 将 RFC8259 公开文本入 PostgreSQL，得到44段原文，检索返回4段。Bing 返回的无关键词匹配结果会被隐藏；百科搜索用于补充背景资料，不是新闻源。部分 Python 文档和新闻站点拒绝或超时，明确失败，不生成替代内容。此免费公开搜索渠道没有稳定性或质量保证，公网阶段应评估适用的正式搜索服务；不宣称接通小红书/抖音热榜。

四角色联调使用模型替身，包含8次调用链路和全部阶段原文输入检查，未新增 DeepSeek 实测费用。公网部署、语义向量模型、平台 OAuth、自动发布/回流、持久后台任务仍为后续工作。

最终验收：全量134项测试及五份前端脚本检查通过；浏览器完成真实百科搜索→正文保存→原文检索，以及资料快照创作至人工确认。测试临时空间已清理，原迁移5个任务未变。详细条件与失败案例见 [验证记录](WEB_DEMO_VALIDATION.md#v06-第二阶段资料公开搜索与网站验收2026-09-21)。
