## 一 产品定位与真实需求

有迹是面向小红书个体商家与小团队的商品文稿工作台。用户提供自有商品或服务资料，系统围绕读者需要了解的问题组织内容，生成有依据、可回查、可修改的笔记草稿。第一批验证场景限定为普通家居、数码配件、手作商品及低风险教程介绍，不以医疗、金融等高资质行业作为初期试点。

产品把创作前的三项决策落到服务端：在篇幅内选择回答哪些问题，资料不足时优先询问什么，参考文章的哪些结构可以迁移。现有四个Agent承担分析、研究、创作、审核；程序负责证据准入、组合选择、资料与稿件版本、费用和最终确认权限。生成稿件、用户采用与平台发布分别记录。

公开报道能够解释为什么值得研究这类工作，但不能代替有迹自己的用户验证。电商在线对小商家的原始采访与记者观察提到内容投入，以及模仿笔记造成的同质化，来源发表于2023年，不能推成2026年商家困难发生率。[电商在线原始采访 机构澎湃号刊载](https://m.thepaper.cn/newsDetail_forward_23071630)

南方周末2026年报道访谈7位遇困用户，反映商家制作内容及理解平台规则的成本。它是目的性个案样本，不证明平台普遍处罚、工具可消除处罚或商家愿意为有迹付费。[南方周末原始访谈 南方网刊载](https://news.southcn.com/node_64549305f1/dac40bdde1.shtml)

市场监管总局2026年7月发布的行动方案关注个体工商户营销能力、产品素材制作及轻量化工具。这是政策方向，不是对本项目的推荐或效果认证。[市场监管总局行动方案](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/djzcj/art/2026/art_883d1cc87d874411aa6330ed2f3f0e7a.html)

| 用户需要完成的工作 | 本项目的技术回应 | 必须验证的结果 |
|---|---|---|
| 短篇幅讲清商品条件与限制 | 需求加权覆盖与预算选择 | 重要问题是否真的出现在最终稿中 |
| 关键资料还没补齐 | 可跳过的提问价值排序 | 问题是否必要以及回答实际耗时 |
| 借鉴写法而保留自身事实 | 结构提取与证据槽位适配 | 是否减少经历和跨商品参数串用 |
| 改稿后还能追溯审核依据 | 快照 版本 哈希与重新审核 | 用户修改后旧结论是否失效 |

上述对应关系是待持续检验的产品假设。本项目不承诺爆款、销售增长、平台合规认证或收入回报；当前没有可以支持这些承诺的独立数据。

## 二 工作流程与系统架构

用户输入主题、读者、目标字数和产品资料后，系统冻结一次创作任务的输入与模型配置。可选联网资料经用户确认导入；未取得正文的搜索摘要不能冒充已读资料。接着按权限、领域、渠道、形式和资料用途检索，四角色共享该任务的冻结证据，避免各角色使用不同版本。

执行顺序为：资料与任务建立 → audience与research并行 → 合并需求与缺口 → 可选追问或继续 → content策略与提纲 → 标题和正文 → reviewer审核 → 用户修改或确认 → 复制及文件导出。需要返修时回到创作与审核，不能以旧报告批准新稿。用户跳过补料时保留缺口并缩小表达范围，不自动补成事实。

| 角色 | 主要输入 | 输出与责任 |
|---|---|---|
| audience 受众角色 | 当前任务与授权读者资料 | 拟定读者问题 区分明确需求与假设 |
| research 研究角色 | 事实资料 原文与来源版本 | 可定位事实 缺口和不能推断的结论 |
| content 创作角色 | 需求计划 事实与适配结构 | 策略 提纲 标题 正文及对话修订 |
| reviewer 审核角色 | 当前完整稿与事实快照 | 逐项问题 引文映射和修改要求 |

系统沿用界面、编排、角色、工具与数据五层组织。FastAPI提供正式接口，Worker领取持久队列并运行LangGraph，SQL业务Run保存权限、预算和批准依据。检查点用于执行恢复，不替代业务授权。模型调用集中经过统一路由与账本，保留实际模型、输入快照、输出、用量和错误。

| 资料组 | 可用于什么 | 不得用于什么 |
|---|---|---|
| methods 方法 | 通用创作方法与检查思路 | 证明某商品的规格或效果 |
| examples 样例 | 段落作用 组织顺序与表达节奏 | 继承参考作者经历 参数和结论 |
| facts 事实 | 本次商品或服务的具体依据 | 自动等同现实真实性已经独立核实 |

检索先过滤再计算相关性。样例要求任务领域交集，渠道与形式一致；事实限定用户、账号、有效版本及所选资料，并进行主题或型号检查。本地向量可用时使用既有语义排序路径，不可用时仅在已过滤集合内降级BM25，并记录实际检索方式，不把词项结果写成语义命中。

三算法是现有链路的决策层，均可单独关闭以支持对照；它们没有新增第五个写作Agent，也没有替模型获得事实判断或批准权限。其任务是产生可解释候选与约束，真正的成稿表现仍由下游审核和人工评价检验。

## 三 需求覆盖优化算法

### 问题与输入

同样300字，按模型输出顺序截取内容可能遗漏重要条件，也可能重复解释同一个卖点。本算法把读者问题作为需求，把具有来源引用的可写内容作为候选模块，在预计篇幅预算内选择组合。需求和模块关系可能由模型提出，但标识、范围、引用与数值合法性由程序验证。

设需求集合R，需求r的重要性为w_r；候选模块j的预计长度为c_j，选择变量x_j取0或1。模块j是否覆盖r由a_rj表示。令n_r为被选模块对r的覆盖次数，预算为B。当前代码的目标为：

`max F(S) = sum_r w_r * I(n_r > 0) - 0.15 * sum_r w_r * max(0, n_r - 1)`

`n_r = sum_j a_rj * x_j；sum_j c_j * x_j <= B`

第一项奖励重要问题被覆盖，第二项惩罚同一问题被多个模块重复占用。0.15为当前工程参数，没有经过真实用户偏好校准；允许用消融实验检验其敏感性。预计长度不是生成稿的实际长度约束，后续必须另查正文长度与必要信息。

### 证据约束与求解

事实断言模块必须通过证据准入：来源属于本任务事实组，引用能够在原材料中逐字找到，覆盖ID属于已建立需求，预计长度为有效数值。提问或限制模块可以作为表达组件，但不能凭空赚取事实覆盖。引用存在只证明位置存在，不证明引文真的蕴含该模块的全部结论。

合法候选不超过12个时，程序枚举至多4096个子集，比较目标值、预计字数和稳定ID，得到当前合法候选池内的精确解。候选多于12个时使用确定性边际密度贪心回退，同时保留选择步骤与排除理由。精确解与贪心轨迹分开保存，不能拿贪心过程冒充枚举过程。

枚举复杂度约为O(2^m * m * |R|)，m不超过12；贪心回退避免候选扩展时指数增长。小候选精确搜索、最大覆盖与贪心选择均为已有方法。预算最大覆盖可参考Khuller、Moss与Naor的1999年研究；本项目加入重复惩罚和不同证据约束，不继承其近似保证，也不主张理论首创。具体改进在于将这些约束用于受限商品写作流程。[预算最大覆盖原论文 DOI](https://doi.org/10.1016/S0020-0190%2899%2900031-9)

### 输出与可解释范围

输出包括选中模块、覆盖与未覆盖需求、预计预算、目标值、求解器、枚举次数、贪心差距及排除原因。若候选池遗漏重要问题，即使精确求解也无法补回，因此同时记录候选需求召回。当前覆盖关系仍可能来自词面或模型建议，必须和最终稿人工覆盖分开报告。

实现入口为backend/planning.py的plan，运行时接入为backend/creation_algorithms.py。可解释记录帮助作者理解取舍，但不是“全文事实正确”或“质量最优”的证明。

## 四 关键资料缺口提问算法

### 目标与决策规则

直接让模型不断要求补资料，会提高交互负担；完全不问又容易遗漏决定性条件。本算法将研究阶段提出的缺口转换为可解释的问题候选，优先考虑影响重要内容、当前仍未覆盖、用户可能回答且成本较低的问题。用户始终可以跳过。

设问题q的重要性为I(q)，回答可解决程度的规则权重为P(q)，回答成本为C(q)，尚未被已选问题覆盖的依赖块集合为U(q)。当前排序值为：

`V(q) = I(q) * (1 + |U(q)|) * P(q) / (1 + C(q))`

I和P是0至1之间的有限规则权重，C为非负成本。P不是经统计学习得到的回答概率。算法每选一问，就从后续问题的新增依赖中扣除已覆盖部分；同义问题按规范化文本去重。分值低于阈值或没有新增依赖时停止，默认最多两问。

当前阈值为0.5。型号、版本或适用条件等缺口可能获得更高重要性；实际可回答程度依字段与规则估计。回答成本也不是实际用户耗时的替身，必须通过真人逐题计时、跳过与主观负担逐步校准。这里没有概率分布或熵差计算，因此称“提问价值启发式排序”，不称已实现信息熵或贝叶斯主动学习。

### 用户交互与状态

系统展示问题、影响范围和可跳过提示；用户回答后建立新输入快照并重新分析，旧计划不能继续当作新事实的有效依据。跳过时只记录“继续按已有资料”，不会删除缺口或把不确定变成已知。需要付费的再次研究调用继续受同一账本和预算限制。

例如，商品介绍缺少确切型号和颜色偏好，若型号会影响参数适用而颜色仅影响表达，规则优先安排型号问题。该例解释决策逻辑，不是证明所有任务都应先问型号；若当前素材已明确型号，不能重复索取。

算法在至多两次选择中扫描候选，通常开销小于模型请求。一般实现约为O(k * Q * D)，其中Q为问题数、D为依赖集合检查成本、k为选择次数；有限输入与确定性排序便于审计。

### 验证与局限

固定标准答案能隔离问题选择规则，但不能代替真人回答行为。真实试用应记录回答数、跳过数、耗时、必要性、实际解决的关键缺口与负担评分。回答数为0时，“解决缺口数除以回答数”记不适用，不能填0或无穷大。当前尚没有8至12位创作者的有效成本校准数据。

实现入口为backend/gap_ranker.py的rank_questions；编排层负责展示、回答、跳过及快照更新，不允许排序函数直接修改审核批准结论。

## 五 证据约束的篇章结构迁移

### 从参考原文到结构卡

参考文章可提供“如何组织”，却不能证明用户拥有相同经历或相同商品参数。算法先把授权样例按段落、换行和句末标点拆为可定位片段，使用规则判断片段主要功能，保存通用作用、顺序、所需资料类型、原文位置与版本哈希。结构卡不保留可直接复用的原文句子或产品数字。

| 标签 | 主要功能 | 典型证据需求 |
|---|---|---|
| HOOK | 引出阅读动机 | 明确任务或读者问题 |
| PROBLEM | 说明需要解决的问题 | 当前用户需求或具体场景 |
| CONTEXT | 交代背景与讨论范围 | 当前任务边界 |
| EVIDENCE | 用资料支撑判断 | 规格 对比 或个人记录 |
| SOLUTION | 组织方案或操作步骤 | 相应步骤资料 |
| WARNING | 说明限制与核对条件 | 已知限制或待核对事项 |
| CTA | 给出下一步行动 | 与正文一致的行动范围 |

篇章功能组织受到Mann与Thompson的修辞结构理论启发，但本项目未实现RST解析器或其关系体系；这里的七标签为产品规则。[RST原论文 DOI](https://doi.org/10.1515/text.1.1988.8.3.243) 标签是规则分类，不是训练过的篇章模型。一个片段同时涉及亲测、比较和参数时，证据需求取并集，不能因为先匹配某个标签而漏掉另外两类证据。分段和标签都可能误判，原文位置供人工回查。

### 匹配与适配

默认按领域、渠道和形式隔离结构卡，再按缺失证据字段数等确定性规则选择。未知或不匹配的样例不自动跨域借用；没有合适参考时使用通用结构，并明确记录回退。当前候选规模很小，不用少量样例估计马尔可夫转移概率，也不宣称模型学会了作者风格。

每个槽位的需求与当前资料字段对照。有支撑的保留；缺少亲测、同属性对比等证据时改成待核对清单或收窄表达，记录缺失项及原因。例如，参考人物“连续使用一个月”的体验段，在当前用户没有个人记录时，不能直接移入新稿。

可用字段只是保守启发式，不是证据充分性的全面语义判断。否定句“没有亲测”不能当作拥有记录；两个型号名字也不能自动证明有可比参数。生成阶段主要提供适配结构和本次事实，完整原文仍留作追溯，避免把原文当填空模板。

### 有限风险提示

正文完成后可与本次参考做有限连续文字匹配，报告位置和长度。这只能提示局部复用风险，不是全网查重、原创认证，也不参与自动批准。结构适配清除缺证据槽位，只能证明替换规则执行；最终稿仍可能重新编造、表达不自然或遗漏必要条件，必须另行检查。

实现入口为backend/structure_profiles.py的extract_profile、select_profile与copy_risk。结构卡与适配理由进入任务快照，供回查。

## 六 工程实现与使用路径

### 证据与版本保护

资料原文、修订版本、切片页码与位置分开保存，检索结果被冻结到任务。资料停用只停止新检索，不抹除旧稿件的来源审计。样例和方法不得被模型改成商品事实来源。用户修改正文、补充材料或替换模型配置后，服务端按相应版本关系使旧审核或计划失效。

审核检查包括事实引用的source_id和逐字quote、稿件定位、当前稿件哈希、既有问题及必须门槛。模型自述approved不等于用户已采用，更不等于已经发布。即使引文有效，也可能出现关系或条件错误；因此系统不提供现实真实性保证。涉及有限资料却扩张使用结论时，需要保留风险并交给人工核对。

### 持久执行与费用

后台任务可在网页关闭后由Worker继续推进；业务产物与节点记录事务提交，节点重放优先复用已落盘响应。租约及fencing拒绝旧执行者迟到写入，取消不能被迟到模型结果覆盖。模型请求前持久预留费用；发出请求后用量未知时停止后续请求，不自动重发。

API密钥只在后端按用户隔离保存，不回显到页面、日志或导出。用户自带模型失败不能静默消耗平台额度；任务冻结所用模型版本。累计费用、实际供应商账单和保守计费上界分别记录，不能把估算金额写成最终实付。

### 用户操作

1. 填写主题、读者、字数及商品资料，确认型号、条件和未知项。
2. 选择是否联网或参考案例，确认实际正文与资料用途后导入。
3. 查看规划依据和关键问题，回答或跳过，按当前资料继续创作。
4. 阅读正文与审核问题，人工修改并复审，确认需要采用的准确版本。
5. 复制文案或导出文件，发布由用户在自己的平台账号中完成。

普通Windows运行包提供本机启动入口；源码部署采用Python 3.12、FastAPI、Worker与持久数据库，依赖锁定在requirements.txt。两种交付的核心源码须由同一提交构建并逐文件校验。Mac上的代码和打包检查不能替代Windows 10或11原生启动、关闭子进程与恢复测试。

当前主线服务小红书商品或服务介绍。历史其他平台适配、模拟运营数据或研究模块不作为已验证的新增平台产品；本轮不把导出、归档和演示账号状态宣传为真实平台发布成功。

## 七 受控实验与人工数据

### 需求覆盖的机制消融

24个固定种子构造任务在相同预计字数与证据准入下比较输入顺序、贪心、正式精确选择和独立枚举。以下是需求权重覆盖的分子分母，不是文章事实正确率或真实用户偏好比例。

| 方法 | 覆盖权重 | 目标值合计 | 允许得出的结论 |
|---|---|---|---|
| 顺序选择 | 242 / 359 | 230.900 | 固定顺序是当前构造基线 |
| 贪心 | 326 / 359 | 316.850 | 该候选池下存在近似损失 |
| 正式精确选择 | 333 / 359 | 328.650 | 与独立枚举目标相等 |
| 去需求权重 | 329 / 359 | 324.950 | 权重会改变当前选择结果 |
| 去证据门控 | 356 / 359 | 356.000 | 覆盖虚高且选入23个无依据模块 |

正式门控配置选入无依据模块数为0；候选需求召回为115/118，说明即使求解最优，候选仍可能遗漏。结果只支持这些受控输入上的计算机制，不能推断实际生成质量提高相同百分比。

## 十 局限与后续发展

### 当前能力边界

三算法改进解决的是有资料约束的创作决策。需求的重要性、覆盖关系和候选完整性仍依赖输入与模型，精确解不保证真实任务最优。提问成本未用真人耗时校准，结构标签是规则，证据字段检查不能充分理解所有实体、属性、单位与条件；有限连续匹配也不能覆盖改写、跨语言和全网来源。

模型主编仍可能漏掉错误；程序只能验证部分格式、来源和版本条件，不能提供现实事实、法律或平台审核保证。没有真实商家持续使用、付费、留存、销售增长或公开发布效果数据。开发者自评应保留并与独立评价分开，不能靠删除失败稿提高完成率。

Windows运行包与源码的逐文件一致性可以复算，原生实机体验则需要Windows测试者。自动化工程验证、跨设备可用性、公开部署和平台授权是不同验收项。用户最终确认不应被批量测试或模型判断替代。
