## 一句话定义

**有迹 = 个人创作者的“内容试飞台”：双情报源（评论区需求 + 搜索意图）→ 可证伪假设卡 → 三层验证（风洞预演 → 小流量赛马 → 实盘归因）→ 校准后的私有经验账本。**

创作工具负责把假设变成内容；有迹的核心任务是帮助创作者用逐步增加的证据检验“这条内容对这个账号、这个目标是否有用”。不预测爆款，不把一次高播放说成稳定规律。

## 用户全流程

1. **发现意图。** 收集两类互补信号：评论区里用户表达的困惑、需求和反对意见；搜索词和搜索趋势里用户主动寻找的问题。每条信号保留平台、时间、原始来源、样本数与授权/采集方式。首期支持用户手动记录或授权导入；不假称已接实时采集，不把单条评论或搜索热度当成普遍需求。
2. **建立可证伪假设卡。** 将信号转成具体、能被结果推翻的假设，至少记录：目标账号与平台、目标（卖货/涨粉/获客）、受众、需求证据、内容角度、期望行动、主要指标及分母、成功阈值、反证条件、观察窗口和已知干扰因素。示例：“对第一次使用剪辑软件的新手，提供字幕制作的完整步骤，相比只介绍功能，能提高每千次有效曝光带来的试用页点击；若点击率没有超过预先设定的差值，就不支持该假设。”
3. **第一层：风洞预演。** 在发布前检查内容是否真正回应需求、事实主张是否有来源、适用范围是否吻合、目标与 CTA 是否一致，以及风险和缺失证据。风洞能排除明显不合格的版本，不能代替真实读者、平台分发或转化测试。报告区分规则检查、模型建议、人工判断和模拟数据。
4. **第二层：小流量赛马。** 用少量读者或平台允许的低成本测试比较内容版本。一次尽量只改变一个因素（如开头或 CTA），预先固定受众、时间窗、主要指标和停止条件；记录每组分配方式、曝光分母、负面反馈和数据来源。平台能随机分流时优先随机分流；自然流量帖子人群不同或无法随机时标为观察性比较，不把差异说成因果。
5. **第三层：实盘归因。** 内容实际发布后，把准确的稿件哈希、账号、平台、发布链接与可追踪的页面点击、有效线索、订单或新增关注关联。优先使用平台授权数据、活动链接/UTM 和用户提供的订单或 CRM 记录。记录付费投流、时段、活动和样本量等混杂因素；平台不提供单篇归因时如实标记“仅观察到关联”或“未知”。
6. **校准私有经验账本。** 只有真实样本和用户审核后的结论，才能形成可复用经验。每条经验保留假设版本、证据快照、适用账号/平台/目标/受众、样本量、区间或不确定性、反例、有效期和人工裁决。证据不足时状态为“待验证”；被新数据推翻、数据修正或用户撤销后，关联计划失效。不同账号的经验默认隔离。

## 三类推广目标，共用一个试验框架

| 目标 | 主要行动与指标示例 | 必须区分的辅助指标 |
| --- | --- | --- |
| 帮商家卖货 | 商品页有效点击、加购、订单、成交额/退款 | 曝光、播放、点赞不能代替订单 |
| 帮创作者涨粉 | 每千有效曝光新增关注、主页访问转关注、后续留存 | 单篇播放或点赞不能代表稳定增长 |
| 帮工具/活动获客 | 有效试用、报名、咨询、激活或合格线索 | 一般链接点击不能代替有效获客 |

三类目标共享信号、假设、版本、验证阶段和经验账本；每个假设只设一个主要目标及主要指标，避免看完数据再挑有利指标。辅助指标可以解释过程，不能取代主要结果。

## 风控在试飞台里检查什么

风控是验证有效性的护栏，不是单独的“敏感词功能”，也不是教程可读性总分。它要查会误导读者或污染实验的具体问题：

- 产品功能、价格、套餐、兼容范围、地区限制和活动期限是否有当前有效的依据。
- “保证涨粉”“高点击率”“爆款”“效果提升三倍”等结果主张是否有可核验样本、比较基线和统计条件；没有就标记未证实。
- 佣金、赠品、赞助关系、版权素材、肖像与个人信息是否有相应披露或授权证据。
- 平台、地区和行业规则来自哪里、版本何时更新；规则检查不承诺“不会限流”或“保证合规”。
- 内容是否兑现假设、面向预定受众并引导主要行动；如果实际改了多个关键变量，要标出该试验不能单独回答原假设。
- 测试数据是否真实、分母和窗口是否完整、是否混入模拟样本、异常流量或付费流量。

例如，巨量算数教程若声称“关联词离中心越近，搜索越多”或“热度上涨就可以做”，需要来源证明图表确实这样定义、以及热度与本次目标相关；不能直接把热度当成销量或流量保证。Reditor 教程若声称“检测违规词可以避免限流”，需要把产品是否有检测功能与是否能避免平台限流分开审查。以上检查不能只从教学视频生成规则。

## 创新点与诚实边界

不能把 AI 写稿、多 Agent、热点发现、内容检查、排期发布或数据看板单独称为原创创新。巨量星图、蒲公英、TikTok One、Hootsuite 等已覆盖营销、创作者协作或运营环节；开源 [Easel](https://github.com/ZJU-REAL/Easel) 也公开宣称覆盖中文平台的趋势、创作、检查、发布和复盘。竞品页面和 README 证明相关产品/项目存在，不足以证明宣传效果，也不能据未公开某个细节推断对方没有该能力。

本项目要争取的独特性是“创作者个人可用的、逐级增加证据的内容试验协议与私有经验账本”：

1. **信号到假设可追溯：** 评论区需求和搜索意图保留不同来源语义、样本和时间，不混成一个无来源的“热点分数”。
2. **先写清怎样算输，再开始发：** 假设卡预先锁定受众、主要指标、分母、成功门槛、观察窗和反证条件，降低事后挑指标讲故事。
3. **三级证据分层：** 风洞只作发布前筛选；赛马看受控小样本差异；实盘看已发布内容的可追踪业务结果。每一步都展示数据来源、版本和因果限制。
4. **错误经验能被推翻：** 经验绑定账号/平台/目标并可更新、撤销；未验证、模拟和观察性记录不会伪装成确定规律。

这是一项待证实的产品差异，不宣称全球首创。要证明不是“豆包生成 + 风控清单”，需与“豆包直出 + 普通人工审稿”做盲测，并把版本、分流和真实结果留证。风险规则也必须来自核验过的官方文件、产品资料或授权数据，不可照抄教程视频。

## 现有能力与新增范围

| 模块 | 当前项目证据 | 试飞台方向的缺口 |
| --- | --- | --- |
| 账号与内容 | 小红书/抖音账号、四角色创作、版本评审、人工批准与发布记录 | 假设 ID 与创作/发布版本绑定 |
| 双情报源 | 用户可导入选题来源；内容风洞可分别录入反馈和材料 | 独立的评论需求/搜索意图记录、样本/授权/来源语义和去重 |
| 风洞预演 | 可用问题卡、来源材料、局部修改、冻结条件复查；当前模拟与真实模型有明确边界 | 改成围绕假设目标、推广主张与发布前质量的预演；模拟不算实测 |
| 小流量赛马 | 暂无随机分流试验 | 版本组、随机/观察性标记、分母、窗口、停止规则；平台允许性实测 |
| 实盘归因 | 可回填真实发布链接和部分人工指标，描述性分析不称因果 | 目标转化事件、活动追踪链接、逐稿件归因状态及付费/自然流量区分 |
| 私有经验 | 已有同账号经验提议、人工接受/撤销及指标修正失效 | 假设证据等级、置信/不确定性、反证与三阶段试验快照统一入账 |

实现优先复用 `backend/operations.py`、账号隔离、版本化操作、内容风洞运行、指标复盘和可撤销经验。新增数据库结构只追加迁移；既有创作、人工批准、任务幂等与模拟/真实隔离继续成立。首期优先用工具/软件推广做完整验证，因为已有材料便于核对功能、适用条件和转化入口；产品模型同时支持卖货、涨粉和获客。首期不依赖自动发帖、私域抓取或爆款预测。

已在网站新增“假设与试飞”页面，并复用现有账号隔离、运营状态版本、幂等命令、创作 Run、风洞 Run 和发布/指标记录：

- 假设卡预先固定卖货/涨粉/获客目标、受众、主要指标、分母、提升门槛和反证条件。创作稿与风洞任务可绑定假设；跨账号和跨假设稿件不可加入其赛马。
- 风洞阶段只接收已结束、当前报告对应当前稿件哈希、且绑定该假设的任务；模拟预演清楚标为模拟。
- 小流量阶段首期登记 A 基线与 B 变体两版、样本单位、分配方式、样本量和结果。系统计算未校准的原始相对差异，不做显著性检验；观察性记录不能称为因果。
- 实盘阶段要求赛马两版都有该假设下的真实发布链接及最新人工指标快照，并使用假设预设的转化指标和分母。仅为用户提供数据，暂未接平台核验、追踪链接验证或自动回传。
- 三阶段完成后由用户裁决；“支持”还需 A/B 赛马及实盘阶段均达到预设差异。经验仍标作探索性，限定同账号、同平台、同目标引用；指标更正会使依赖经验失效。

暂未实现：渠道自动采集、平台授权发布/随机分流/指标回传、UTM 与订单系统核验、置信区间和显著性分析、混杂因素建模与统计因果结论。没有真实账号数据前，演示与单元测试不能作为推广效果证据。

## 验证方案与失败条件

第一轮比较“豆包直出 + 普通人工审稿”与“有迹假设卡 + 风洞预演”，固定素材、目标和编辑权限，盲审重大无依据主张漏检率、误报率、假设与 CTA 匹配、作者修改时间、采纳率。验证风洞阶段有无价值，不能拿模拟报告证明增长。

第二轮先做真实读者小样本或平台允许的低流量试验，预注册主要指标、样本/曝光分母、观察窗和停止条件。分流无法随机时只报告观察性结果。第三轮仅在有授权发布、追踪链接或可靠平台/商家数据时做实盘归因；按目标分别报告有效点击/订单、关注转化或有效线索。报告样本量、缺失、付费/自然流量和不能排除的混杂因素。

停止或回退条件：评论/搜索信号无法合法、稳定地取得；重大主张漏检不优于基线；误报和整理成本抵消收益；假设卡过重导致作者放弃；平台不允许公平分流却仍无法避免因果误述；真实数据无法连接内容版本；小样本结果不稳定或没有可重复改善。发生时先缩小目标、改进记录和判断规则，不添加更多 Agent 来掩盖证据不足。
