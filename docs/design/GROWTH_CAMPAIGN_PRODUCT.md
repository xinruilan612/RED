# 有迹：目标驱动的社媒推广闭环

状态：产品方向与验证方案，尚不表示下列新增能力均已实现。核对日期：2026-09-27。

## 产品定位

有迹帮助小团队围绕一次推广活动完成：明确目标和受众、整理可用事实与素材、制作多版本内容、检查风险并人工定稿、按平台发布、记录真实结果，再形成经用户确认的下一轮建议。

卖货、涨粉、工具或活动获客是同一活动模型的不同目标，不是三个互不相干的产品。每次活动必须指定一个主要目标和一个可观测行动：卖货对应商品页访问/有效订单，涨粉对应新增关注及主页访问转关注，获客对应有效咨询/报名/激活。曝光、点赞等只作为辅助指标。缺少可信数据时显示“未知/未接入”，不能补零或归因。

## 用户流程

1. 建立推广活动：选择账号、平台、目标、受众、商品/工具/活动、行动入口、推广关系、地区与观察窗口。
2. 建立事实包：录入或导入产品功能、价格、兼容范围、活动时间、案例、授权素材和来源；标明来源、适用范围、有效期和责任人。
3. 生成内容方案：按目标产出选题、主张、内容草稿、素材建议和 CTA。每个重要事实主张都关联事实包中的依据；没有依据时必须降级为待核实，不可编造成果或亲身体验。
4. 发布前审查：把逐句事实核查、平台规则、商业披露、版权/隐私、目标与 CTA 一致性分开显示。输出问题位置、依据、规则版本、严重程度、置信/未知状态及建议；用户可接受、修改、驳回或申诉。
5. 版本化批准与发布：批准绑定具体稿件哈希、账号、平台和发布时间。首期保留人工发布与回执录入；平台接口须按账号授权和实际审批逐一接通。
6. 结果回流：导入平台原始指标或明确标识为人工填报；记录曝光分母、花费、受众/时段、内容版本、链接点击、关注、线索、订单及不良反馈。系统按目标解释结果，数据不足时不下结论。
7. 用户确认后更新经验：经验限定账号、平台、活动目标、来源及有效期；修改指标或撤销经验会使依赖它的建议失效。

## 风控究竟检查什么

风控不是“教程写得顺不顺”，也不是跟着视频抄敏感词。它围绕会影响消费者决策、平台准入或作者信誉的具体风险工作：

| 风险类型 | 例子 | 系统应给出的处理 |
| --- | --- | --- |
| 产品事实 | “支持 TikTok 商品链接贴纸”“自动识别字幕”“背景移除免费” | 找到适用的官方说明、版本/地区/套餐；缺证据则要求核实或改成有限表述 |
| 效果与比较 | “高点击率封面”“保证涨粉/爆单”“比其他工具快 3 倍” | 要求可复核数据、样本和比较条件；无证据时禁止作为已证事实 |
| 价格与活动 | 折扣、限时、库存、免费试用 | 核对金额、地区、时间窗、限制和落地页；过期后自动标记失效 |
| 商业关系 | 佣金、赠品、赞助、联盟链接 | 提示披露义务及所在地区/平台规则，保留人工确认，不替代法律意见 |
| 版权与隐私 | 音乐、图片、用户评价、人物肖像、客户数据 | 检查授权和使用范围，缺少凭据时阻止批准或升级人工复核 |
| 平台规则 | 格式、导流、广告标识、行业限制 | 记录平台、地区、规则来源和版本；不能承诺“不会限流”或“保证合规” |
| 目标错配 | 内容引导点赞，但活动目标是报名或成交 | 检查承诺、CTA、落地页和目标行动是否一致 |

例如，巨量算数教程把“关联词离中心越近＝搜索越多”当成操作规则时，风控要问官方材料是否真的定义了这个图形含义；“热度上涨就可以做”也不能直接推导出会有流量或销量。Reditor 教程中“违规词检测避免限流”应被拆成产品能力证据与平台结果承诺：前者需官方功能来源，后者不能由一个词库扫描证明。所有检查结果均标明是规则检查、模型建议、人工裁决还是实测结果。

## 创新主张与边界

不能将多 Agent、AI 写稿、统一日历、平台发布或数据看板单独称为原创创新。公开产品已覆盖这些能力：巨量星图、蒲公英与 TikTok One 提供营销/创作者合作及投后环节；Hootsuite 将内容、审批、发布、监听和分析集成；开源 Easel 已公开宣称覆盖中文平台的趋势、创作、检查、发布和复盘。

本项目应争取并验证的差异是“推广主张证据—风险裁决—稿件版本—真实结果”的可审计闭环：

- 每条关键主张可回到原始依据、适用对象、时效与授权，而不是只给风险分数或敏感词命中。
- 每项问题绑定规则来源和版本，说明问题位置、影响目标及为何建议修改；有争议时允许人工裁决并保留记录。
- 修改、批准和发布对应不可混淆的稿件版本；同条件复查冻结目标、依据、规则及模型配置。
- 结果回流对应具体内容版本和目标，区分真实平台指标、人工录入、模拟值，并显示样本量与归因限制。
- 学习可撤销且按账号/平台/目标隔离，不把一个账号的经验当成另一个账号的事实。

这是一项待验证的产品机制，不宣称全球首创。公开页面没有展示某项功能，不足以证明竞品没有该能力。项目现有账号、创作审批、指标录入、规则分析、资料来源快照及可撤销经验可复用；内容风洞目前主要解决发布前检查与局部修改，不等于已具备上述统一活动和转化评估闭环。工程真实性与新定位的差异化证据须分别验收。

## 首期实现边界

复用现有账号、创作、审批、来源快照、指标录入、分析和经验模块，新增统一 Campaign/目标契约，将内容风洞变成活动中的发布前审查环节。目标枚举首期包含 sales、audience_growth、lead_acquisition；风险规则与指标必须按目标、平台、地区版本化。首期不依赖自动发帖或私域采集，不承诺预测爆款；手工回填须明确来源。优先用工具/软件推广作为端到端验证垂类，因为现有样稿集中于工具教程，功能、套餐、平台适用范围和行动入口都可逐条核验；架构仍保留卖货与涨粉目标。

自动平台接入、复杂投放归因、跨账号策略迁移和模型预测排在后续，只有在官方权限与真实数据可用时启动。不要将旧的 tutorial-readability 检查结果改名为完整营销风控。

## 验证与停止条件

先冻结工具/软件推广样本和规则，与“豆包直出 + 普通人工审稿”对比。盲审指标包括：重大无依据主张漏检率、误报率、规则来源准确率、CTA 与目标一致率、作者采纳率、完成耗时。报告原始分母、分歧和置信区间；样本少时称探索性结果。

随后做授权的小流量真实试测，分别记录曝光、花费、落地页点击、有效线索/激活或目标适配指标，并记录平台、账号、受众、发布时间、内容哈希和是否付费。优先采用平台允许的随机增量实验；无法随机时标为观察性比较，不声称内容导致增长。未收集有效样本前，产品质量可报告工程测试与盲审结果，不能写“帮助商家增收/保证涨粉”。

停止扩展的条件：重大主张漏检没有优于基线；误报让作者花费明显增加；来源无法核验或维护成本过高；修改采纳率低且没有减少检查时间；真实试测没有可重复的目标行动改善。出现这些结果时先改规则和工作流，不堆更多 Agent。
