## 分类和实际检索

`config/creation_taxonomy.json` 配置领域、渠道、形式及检索限额。领域可多标签，配置可扩展；渠道与形式分开。任务通过 `creation` 传入领域、渠道、形式、目标和字数，未指定项由 `backend/creation_taxonomy.py` 识别，关键歧义要求选择领域。识别是可检查的规则判断，不宣称模型分类准确率。

资料分类随版本保存，切片通过版本关联保留分类、来源、页码和位置。材料类型为 method（通用方法）、example（领域样例）、fact（事实资料）。已有资料补标会追加版本，记录推断来源，不改旧版本和旧任务快照。未知领域或未知形式的样例不进入匹配样例组。

网页 `POST /api/runs` → `Service.create` → `Knowledge.grouped_retrieve` 冻结三组材料、分类、实际过滤条件与缺口：

- 方法：当前领域或通用领域，渠道和形式适用；允许明确的通用渠道与通用形式。
- 样例：至少一个任务领域交集，并且渠道、形式完全匹配。
- 事实：限定当前账号、有效版本和所选资料，要求主题相关，含产品型号时检查型号；不限制发布渠道或形式。资料分类为事实不代表已独立核实真实性。

权限、资料状态、领域和形式筛选在真实向量计算之前完成。复用本机 BGE 模型，按已筛选候选分批编码、余弦召回，再以余弦相关度和词项覆盖率重新排序；这是确定性的二次重排，不是交叉编码器。每组数量、每片长度、三组总长度由配置限制，当前分别为 2/3/4 条、700 字符和 5200 字符。用户自行提供的任务素材另受原有 8000 字符输入限制。

模型缺失或向量计算失败时明确记录不可用，不冒充向量结果。没有匹配样例时保留空组与缺口，使用本次事实和适用方法，不回退到其他领域样例。旧的资料库手动检索接口保留原功能；网页创作使用上述新分组路径。

## 运行时规则和参考记录

实际模型输入由 `backend/live.py:messages_for` 构造，不从角色说明文件加载。任务分类及三组输入进入持久 Worker 的所有角色调用。样例正文只出现一次；事实正文在材料区，其他位置保留索引，避免重复放大上下文。

内容创作的决策顺序是用户明确要求、适用渠道与形式、通用方法、样例风格。样例只提供开篇、节奏、结构与表达参考；不继承作者经历、测试数据和产品结论，不做同义词替换式复制。材料内指令不能覆盖运行规则和用户任务。不保证“必爆”，关键事实缺失时进入补充资料流程。

代码校验研究事实及审核引用只能来自本次事实组或用户本次素材，拒绝把样例和方法当事实引用。发布正文不加入来源 ID 或内部核验过程；审核的 `reference_records` 独立保存分类、三组来源 ID、样例缺口、采用说明与事实引文映射，并随节点、模型账本及稿件版本保留。

网页展示当前任务及历史稿件对应的冻结检索记录。模型收到材料、模型自述采用和独立验证是不同证据；参考记录不会把“输入过样例”写成“已经证明使用了样例”。

## 验收入口

`tests/original_creation_cases.py` 为自编受控资料，包含美妆、摄影、数码、家具、同领域换口播及园艺无样例六个场景。产品与参考作者经历均为虚构验收材料，不能作为真实产品功效、真实用户反馈或平台效果证据。

`scripts/original_creation_acceptance.py --execute-authorized` 使用生产 HTTP 接口与独立 Worker 运行真实模型，仅在已获费用授权后执行。本轮授权总上限 US$0.50，实际费用、分类、筛选条件、命中片段、最终成稿与引用检查以验收报告为准。原创检查比较本次参考样例的独特表达与经历，不宣称完成全网查重。

工程回归覆盖真实 PostgreSQL、账号隔离、资料版本、检索前过滤、事实渠道独立、缺样例、缺向量模型、引用边界、实际运行时输入及网页表单。验证结果另记，未执行的检查不计为通过。

实际结果见 [六场景验收报告](../evidence/original-creation/REPORT.md)。复审只携带当前完整稿件、事实正文与上一轮待修问题；完整检索过滤条件和历史审核记录仍留在冻结快照中，避免重复输入耗尽预留预算。六场景全部完成模型审核，但人工表达核验的瑕疵与原创检查范围仍须单独查看报告。
