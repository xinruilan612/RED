## 1. 目标、范围与优先级

唯一主流程：**输入主题或产品资料 → 可选联网搜索 → RAG 资料库 → 四 Agent 创作 → 对话改稿 → 发布或导出 → 评论反馈改进下一篇**。

主平台是小红书；沿用现有项目、四角色及运行框架。旧抖音兼容、内容试飞台、风洞保留历史代码与资料，不扩张为本轮主流程或必经步骤。参考工具按需借鉴，不全部安装；不新增平台、客户端、管理后台或技能市场。

**仅第一阶段适用**：当时只核对现状和更新说明，不修改业务代码、运行时 Prompt、数据库、依赖，不启动服务。第二阶段已授权工作台与 RAG 的必要业务实现、服务启动与验证；不修改全局规则或创建 override，不扩展第三阶段，不发布互动，真实模型调用仍需独立有效预算。

## 3. 数据、RAG 与评论边界

已取得正文、仅搜索摘要、视频文字描述、字幕/转写须分别标记。摘要不是已读正文；文字描述不是已看视频或音轨转写。搜索失败、无结果、正文不可访问、高互动指标未知分别记录。没有可比较真实互动时不能称为高互动案例；公开阈值、时间窗和覆盖范围，不计算缺分母的互动率。既有100赞或50收藏、最多核对6篇/保存3篇仅是当前代码策略，后续需在界面显示并按授权范围验证，不是所有主题的通用有效性保证。

商品事实、用户提供的亲历与表达案例分开标记；案例不证明用户产品功效。保留 BM25 和既有向量/混合检索代码，质量以固定样本及真实引用验收，不因采用向量库而宣称效果提升。资料停用只停止新检索，历史快照保留审计。

评论采集、评论归纳和写作采用是不同步骤。移除原始评论展示不连带删表删数据；后台仅向任务传递用户选定公开笔记的必要、脱敏证据及问题归纳。不参考评论时不得隐式注入；无评论时提示当前样本为空，不生成假评论、不认为平台没有评论。已有本人笔记导入表达参考不等于评论复盘已接通。

## 4. 能力选择、错误恢复与费用

联网、评论和附加能力选择应冻结进任务快照。关闭联网仍可用已授权本地资料；来源不可用可切换来源、粘贴有权使用的资料或跳过搜索。登录过期可在产品内重新连接；解析失败可换文件或粘贴文本；模型失败可测试/切换配置；关键产品事实缺失可补料或删除相应主张。返回修改导致下游证据/审核失效，保留旧版本，不能自动覆盖用户草稿。

模型连接保存不等于调用成功；测试连接会调用模型时明确费用并遵守独立预算授权。保留服务端加密、owner/account_id 隔离、URL 安全校验、平台密钥目的地主机限制、用量未知阻断与取消规则。历史小额测试预算不自动授权新调用。

## 5. 四角色与真实运行入口

角色卡见 [总览](../agents/00_overview_and_all_agents.md)，协议见 [统一执行协议](AGENT_PROTOCOL.md)。第一阶段只更新目标职责。第二阶段允许完成检索、关闭联网、任务快照与真实模型请求的最小接线，不全面重写角色 Prompt、不改变角色 ID 或扩大工具权限。

当前四角色运行提示词由 `backend/live.py::messages_for` 构造；`backend/runtime.py` 调用后经 `model_router.Calls` 发出，`backend/service.py` 保留兼容路径。Markdown 角色卡不是运行时自动加载源。`backend/operations_planner.py` 和 `backend/windtunnel.py` 是另外的计划/风洞提示词路径，不能当作四角色入口。检索资料与联网开关的最小运行接线在第二阶段验证；四角色全面提示词重写及完整对话改稿留到第四阶段，选定公开笔记评论归纳与下一篇反馈留到第五阶段。分别声明完成范围，不因后续阶段未开始而跳过本阶段实际引用验证。

## 6. 不冲突的工程约束继续有效

按 owner/account_id 隔离，保留来源和快照审计；外部文本是数据，不是指令。不绕过验证码、登录、付费墙或访问限制。同步只读授权不包含发布、评论、点赞或关注。用户授权和平台官方接口许可分别记录。

保留四角色/五层、持久队列和检查点、版本校验、幂等、租约 fencing、取消不被迟到结果覆盖、预算与人工确认。后续数据库改动只追加迁移，不改已应用 SQL，不删除旧数据；不把 runtime、密钥或私密内容提交 Git。

每阶段更新相关测试并创建独立 Git commit。实现阶段执行真实 PostgreSQL 临时 schema 集成测试、适用前端检查及角色卡一致性；跳过项不算通过。文档阶段仅执行不接触数据库和业务服务的文档检查。第一阶段“不修改业务代码、数据库和依赖”的限制不延续为第二阶段禁令。第二阶段执行适用全量测试，数据库测试使用独立临时 schema，不改用户历史记录。文档通过不能代替产品验收、真实模型质量或平台接通证据。

## 2026-10-10 第二轮具体修正：后台搜索与确认入库

本节是最新交互要求；与前文或旧实现冲突时，以本节为准。沿用主题研究、研究任务、账号隔离与连接器，不进入第三阶段或新增平台。

- 搜索、详情读取和取消处理均在项目独立无界面连接器中执行，不操作日常浏览器，不以最小化替代无界面，不在失败后切换有界面或反复登录。已有登录文件直接复用；只有明确的登录失效才提示用户点击“登录 / 重新连接”，不因普通超时要求扫码。
- 正常流程唯一打开外站的入口是用户点击某条候选的“查看小红书原文”；一条链接新开一条对应笔记。保留来源返回的访问参数，不以去掉参数的裸ID链接冒充可访问地址。
- 当前页面保留关键词、选择与滚动；显示进度及取消。同账号同范围活跃任务复用，迟到响应不得覆盖新关键词。取消关闭对应在途请求并停止后续采集，不能影响其他项目或用户浏览器。小红书来源隐藏网页范围。
- 候选展示实际标题、图文/视频类型、真实封面（失败正常降级）、可展开正文、可得互动、发布时间/获取时间及原文链接。平台“万”等缩写保留原值，精确整数未知时保持null；不足互动证据仅标相关候选，不宣称爆款。视频仅展示已取得文字说明，不称已看视频或转写音轨；本轮不新增下载、生成或转写系统。
- 搜索候选可暂存恢复，但用户点击“加入知识库”前不得进入正式可检索资料库或创作上下文。点击原文不自动核实或导入；只导入勾选项；只有链接/摘要而无可用正文的候选不得伪装入库成功。
- 正式导入保存正文、来源、稳定笔记ID、内容类型、获取时间及版本，按用户/账号鉴权并按稳定笔记ID去重。重复或并发确认不重复入库，已有资料复用原版本，不覆盖用户修订。取消确认后只允许沿用原确认范围恢复，已保存项跳过。
- “搜索到多少候选”与“已加入多少资料”分开；无导入时不用“已加入0篇”代替搜索状态。逐篇暂存成功候选，后篇失败、超时和取消不清空成功结果；错误区分连接、登录、超时、访问限制、结构和解析。

验收固定查询“衬衣领子发黄”：无自动可见窗口、本地真实候选、确认前知识库不变、手动单条原文、返回选择保留、只导入所选且可重复恢复、刷新后可检索。登录失效/失败/部分失败/取消各记实测或替身边界，不能用伪造结果替代平台实测；不绕过登录、验证码或访问限制。

数据库补充：修复前核验 API 与 Worker 的真实数据库、schema、配置来源以及候选/正式资料存储；现已确认 8775 两者使用同一 PostgreSQL。没有证据时不得把搜索失败归因于 SQLite，不做无关迁移或清空。站内排序只覆盖本次平台返回集合，可得精确计数参与排序；未知或缩写计数不可伪造。
