版本：设计草案 1.0；日期：2026-09-21。

状态：待实现。本次交付说明书与文档检查，不包含产品功能实现或真实运营效果证明。

开发分支：`codex/skill-service-promotion`，从本机 `main` 的 `90d8ae9` 创建。分支创建时已有旧 starter 的三处未提交删除，不属于本需求，不得顺带提交。

## 1. 产品定位与核心决策

有迹保留推文创作，增加“接单推广”核心应用场景，帮助有技能、有作品的人把真实积累转化为持续社媒内容，并根据客户反馈改进推广。

两个入口共享同一创作底座，不建立第二套账号、资料库、四角色流程或发布系统：

| 入口 | 用户意图 | 交付 |
| --- | --- | --- |
| 内容创作 | 我有经历、素材或主题，想分享 | 素材梳理、选题、推文生成、编辑、审核、人工确认 |
| 接单推广 | 我有技能、作品和服务，希望获得合适的客户咨询 | 服务档案、客户问题选题、推广内容、人工发布记录、咨询复盘 |

推广目标 → 服务与作品素材 → 客户问题与选题 → 原有创作流程 → 人工发布 → 咨询反馈 → 下一轮建议。

本场景的产品价值假设是：减少用户反复整理业务资料的负担，让内容与客户决策关联，并让下一次创作利用可追踪的真实反馈。尚未证明优于通用聊天工具，不承诺涨粉、爆款、订单或收入。

## 2. 首批用户与范围

首个验证场景为大学生摄影师：已有少量作品，希望在指定学校或地域承接毕业照、个人写真等拍摄服务。没有成交历史也可以使用；没有素材时先补料，不编造案例。

产品数据结构为其他个人服务保留扩展空间，但首版不同时建设家教、手作、设计等行业模板。成熟品牌主理人、多门店和营销团队留待首个场景验证后评估。泛自媒体零基础赚钱培训不在首版范围。

小红书、抖音仍为目标平台；首轮体验验收优先使用小红书图文场景。平台适配不得冒充官方接口已经接通。

## 3. 首版交付范围

### 3.1 服务与作品档案

在已有社媒账号下新增服务档案，首版一次推广任务选择一个服务。

- 必填：服务名称、提供的具体服务、目标客户、服务地域或线上服务方式。
- 选填：价格或价格区间、计价单位、服务包含与不包含事项、可约时间、常见问题、用户希望公开的预约方式。
- 所有字段区分“内部参考”和“允许公开”；价格未填不生成报价，档期未填不生成可预约承诺。用户填写不等于自动授权写入文案。
- 作品记录包含标题、用户确认的案例描述、本人承担的工作、可支持的事实、关联资料版本及可用状态。首版支持描述和用户提供的作品链接，链接不自动抓取。
- 图片托管、自动视觉理解和视频生成不是本轮前置条件。没有读取图像时，界面和 Agent 只能声明依据用户提供的描述，不能声称看过作品。
- 作品进入公开稿前须由用户确认可公开使用；涉及人物或客户的资料不默认获得公开许可。原始客户聊天、电话、微信号不作为必填资料。
- 停用档案或作品后不用于新任务；已有任务保留版本快照。失效资料对正在编辑稿件的影响须提示，涉及公开资格、价格或档期的变化要求重新检查和人工确认。

### 3.2 围绕客户问题的选题

推广简报选择账号、服务、目标和素材。首版目标枚举为“被发现”“建立信任”“促成咨询”，不让用户输入预期收益就生成保证。

每张选题卡包含：目标客户、客户问题、内容角度、目标、可引用作品或事实、缺失素材、建议行动引导、依据类型。

客户问题来源必须标注为用户提供、真实咨询汇总或模型假设。没有历史时允许给出假设，但不描述为已证实的受众洞察。首版提供少量可编辑候选，用户明确选中后才进入创作，避免默认批量调用模型。

示例：客户担心不会摆姿势 → 用户提供真实引导过程 → 推荐“第一次拍写真如何准备” → 缺少过程材料则建议补拍或补充记录，不虚构客户评价。

### 3.3 共用推文创作流程

选题进入已有 audience / research / content / reviewer 四角色流程，继续支持编辑、返修、复审和精确版本人工确认。

推广场景增加的创作上下文包括服务与作品快照、客户问题、目标、公开字段、有效反馈依据。普通内容创作不要求填写这些信息，也不自动加入营销话术。

输出应说明采用了哪些真实材料、哪些判断仍为假设、用户需要补充什么。行动引导应与用户明确的公开信息一致，不自动添加联系方式或不适用的平台引流方式。

用户修改正文、报价、档期或所选作品后，按版本规则重新审核。档案在任务执行中改变时，旧任务不能悄悄读取新版并继续生成；继续使用明确快照或由用户发起更新后重新审核。

### 3.4 人工发布与轻量咨询反馈

复用已有人工发布记录，绑定账号、平台和确认稿版本。创作 SUCCEEDED 不代表发布成功；MANUAL_REPORTED 不代表平台核实成功。

用户手动记录一个匿名咨询事件，最少填写时间、所咨询服务和问题分类，可选简短脱敏摘要。首版不接私信，不自动联系客户，不管理支付、合同、订单或客户通讯录。

归因由用户选择：

- 关联一篇明确的已发布内容：保存 publication_id 以及“客户自述”或“用户判断”等依据。
- 由多篇内容影响：记录为多触点，不强行分摊给每篇。
- 来源未知：保留未知，不自动匹配最近发布的内容。

同一次咨询只保存一次；重复提交由幂等键拦截，疑似重复允许用户确认合并或撤销。复询和新的独立咨询由用户判断，首版不收集个人身份以做自动去重。

“有效咨询”由用户标记为待判断、有效、无效，并附可选原因。有效可指具体询问服务内容、档期或报价且与服务范围相符；同行交流等可标无效。该标记是用户报告，不是平台认证。

### 3.5 复盘与下一步建议

复盘展示固定观察窗口内的发布、明确关联咨询数、有效咨询数、未知来源与多触点数量、反复出现的客户问题及待补素材。未填写反馈不能当作零咨询：用户明确确认“本窗口无咨询”才记录零。

首版不默认计算曝光到咨询的转化率，不推断成交金额，不把点赞高等同业务价值。不同窗口、未完成观察、投流与未投流等记录不得直接混算并输出优劣结论。

下一轮建议须链接具体问题和证据，例如“多次询问是否提供服装，但现有内容未说明，建议补充服务说明”。少样本只做描述和待验证建议，不推断因果或稳定增长规律。

候选经验需人工接受后才影响之后的选题和计划；支持拒绝、撤销。反馈修正或删除后，依赖它的分析、经验和计划失效，旧任务快照留作审计。偏好、真实事实、观察结果和策略假设分别保存。

## 4. 完整使用示例

以下为虚构验收场景，不是真实运营效果。

1. 学生摄影师选择已有账号，填写毕业照服务、学校、服务内容与公开字段，添加两条真实素材格式的虚构作品记录。
2. 选择“建立信任”，系统提供“不会摆姿势也能拍好毕业照”的候选，依据是用户描述的引导过程；标记缺少过程截图。
3. 用户补充文字过程或换成素材充分的角度，选择选题进入原四角色流程。
4. 用户修改文案中的服务内容，系统使旧审核失效，重新审核后确认新版本。
5. 用户自行发布并回填发布记录，系统不伪造平台回执。
6. 回填两次明确来自该内容的咨询、一次来源未知的咨询；其中一个明确咨询被用户标为有效。界面分别显示，不合并成三次该篇转化。
7. 系统根据客户反复询问的服务内容提出下一篇建议；用户接受后才进入计划。
8. 用户撤销一条反馈，对应分析和经验失效；原稿和历史快照不被改写。

## 5. 页面与交互

沿用现有网站布局、登录和账号选择，在创作入口提供“内容创作 / 接单推广”的场景选择。

| 页面或区域 | 首版变化 |
| --- | --- |
| 账号中心 | 服务档案、作品记录入口及可公开字段 |
| 接单推广 | 选择服务、目标、作品，查看和编辑客户问题选题 |
| 原创作页 | 显示推广简报摘要与依据，继续原有创作、改稿和审核 |
| 发布记录详情 | 人工咨询录入、归因方式和观察窗口 |
| 运营复盘与计划 | 咨询问题、数据缺口、候选经验及下一步建议 |

空状态给出具体下一步：无服务先建档，无作品先提供经历或案例描述，无历史则展示假设，无反馈则提示待回填。界面使用“依据不足”“来源未知”等文字，不填造评分或成功率。

## 6. 与当前工程的关系

当前仓库包含 backend.api、账号与运营模块、analytics、planning、资料检索、Model Router、Worker 与持久执行链。本轮仅核对文档和部分源码职责，未重新验收所有既有产品能力。以下为待实现的接入方案，不表示这些模块已经支持接单推广。

| 现有能力 | 建议接入方式 |
| --- | --- |
| Auth、accounts、operations | 复用 owner/account_id、CSRF、事务、版本与幂等守卫 |
| knowledge 与证据快照 | 关联可用文字资料版本，保留出处；不自动抓取作品链接 |
| 原创作运行协议 | 增加可选场景上下文，普通创作默认保持原行为 |
| audience | 区分一般读者和潜在客户，提出带来源的客户问题 |
| research | 检查作品与服务事实、公开范围、缺失材料 |
| content | 按被发现、信任、咨询目标组织内容，并给出依据 |
| reviewer | 检查事实、价格档期、隐私公开范围和过度承诺；修改必复审 |
| analytics、planning | 扩展咨询统计、依赖失效及人工接受后的计划连接 |
| model_router.Calls、runtime、worker | 所有新付费调用继续走既有预算、快照、租约和恢复守卫 |

不增加独立的销售 Agent，不用自由文本提示绕过结构化权限检查。统计与失效由确定性代码执行；解释性生成如需模型，必须走统一调用入口并计入现有预算。

## 7. 数据与契约草案

以下为逻辑对象建议，尚未成为数据库或 API 契约。第一阶段需根据现有 DTO、Operations schema 和机器契约确定兼容的版本扩展；不能只增加前端字段而绕过严格后端校验。

| 对象 | 关键字段与关系 |
| --- | --- |
| ServiceProfile | id、owner、account_id、version、服务字段、公开字段列表、active |
| PortfolioItem | id、owner、account_id、service_id、version、描述、资料引用、公开确认、active |
| PromotionBrief | 场景、account_id、service_id/version、目标、客户问题与依据、作品版本、公开字段快照 |
| InquiryFeedback | id、owner、account_id、service_id、时间、问题分类、脱敏摘要、归因类型、可选 publication_id、归因依据、有效性、version、撤销状态 |
| FeedbackWindow | account_id、service_id、窗口起止、时区、是否确认回填完整、明确零咨询确认、version |
| PromotionAnalysis | account_id、service_id、窗口、依赖反馈版本、观察结论、待验证建议、有效状态 |

owner 必须从服务端身份解析，所有关联验证同 owner、同 account_id；明确关联的发布还须与服务场景一致。客户端提供合法 ID 不意味着拥有访问权限。模拟与真实数据保持来源隔离。

新增对象优先保持清晰的关系与版本依赖。新核心 SQL 只能追加 backend/migrations.py 的迁移版本，不能修改已应用迁移。API 路由在契约阶段确定，沿用现有风格，不另开一套认证和任务系统。

旧任务没有 PromotionBrief 时视为普通内容创作；旧发布不能自动推断推广服务或历史咨询。更新服务不回写旧稿、旧快照或确认记录；新创作和继续发布时校验当前有效性。

## 8. 分支开发与分阶段交付

本轮授权范围是说明书与独立分支准备，不自动开始以下产品实现。后续开发在本分支按阶段推进，每阶段更新相关测试、完成验证并独立提交。

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| P0 契约与基线 | 核对当前 checkout、运行服务和机器契约；明确数据/API、公开字段、归因、版本失效与兼容策略 | 契约、迁移与隔离测试明确，普通创作基线可复现 |
| P1 档案与素材 | 服务和作品记录、公开字段、账号隔离、停用与版本 | 可保存和更新，跨账号拒绝，历史快照可追踪 |
| P2 选题到创作 | 场景入口、客户问题选题、快照传入四角色 | 普通创作不受影响，推广稿可生成并人工修改、复审、确认 |
| P3 反馈到复盘 | 人工咨询、窗口、归因、确定性统计、经验失效与计划 | 未知与零值不混用，修正可撤销，下一轮引用有效证据 |
| P4 体验与效果验证 | 完整浏览器流程、进程恢复、同材料对照、小范围摄影师试用 | 分别记录工程通过、真实模型效果、用户反馈和未完成项 |

Git 分支只隔离代码历史，不隔离数据库、端口、环境文件或未提交变更。若主线与本分支需要同时开发，应使用独立 worktree、独立开发数据库、端口及对应 Worker，不能让两个分支对同一开发数据库同时迁移。创建 worktree 和运行环境时另行核对，不复制或提交密钥。

合并前同步主线并处理迁移版本冲突；已应用迁移不可原地改写。测试使用临时 PostgreSQL schema，产品演示使用独立开发数据库。停用入口即可停止新场景任务，但数据库回退需按备份和迁移方案操作，切换 Git 分支不是数据库回滚。

下表全部是未来功能验收要求，本次文档测试通过不代表这些行为已实现。

| 编号 | 场景 | 应有行为 |

## 10. 如何验证用户价值

先招募少量符合场景的摄影师做形成性试用，记录人数、背景、素材条件、失败案例和访谈反馈，不用小样本宣称普遍有效。

同一份账号、服务和作品材料，分别用通用聊天工具与本产品完成选题、成稿和一次反馈后的调整；允许对照组正常追问，避免用差的提示词故意降低对照表现，条件允许时交叉安排顺序。

记录资料整理与操作时间、事实错误或无依据承诺、用户修改量、建议采纳、是否理解下一步以及是否再次使用。订单、收入和流量仅在用户自愿提供且可解释观察窗口时记录，不直接归因于产品。

预期创新需以试用证据支持：作品与事实如何影响选题、客户问题如何改变稿件、反馈如何改变下一轮计划。仅有多个 Agent 名称或流程动画不算价值证明。
