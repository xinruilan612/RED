# 核心算法创新：可解释内容实验决策

## 产品差异

通用聊天工具擅长一次性生成文案，但通常不会延续同一账号的实验、发布指标和证据链。本项目本身覆盖三种强度：一句话极速出稿、证据驱动专业创作、跨期运营实验。极速模式只做一次完整初稿生成和一次独立审核，避免日常内容被多阶段流程拖慢；专业模式保留多角色分工、资料证据、返修和审计。

完整闭环为：项目内极速或专业创作 → 独立审核 → 人工确认 → 发布记录 → 同窗口指标 → 描述性分析 → 实验决策 → 人工接受 → 带控制变量创作 → 新一轮观测。

## 两档创作算法

- `quick`：生成角色直接读取需求、素材、账号档案与已接受实验，一次输出完整初稿；随后由独立审核角色进行第二次调用。正常链路固定为 2 次模型调用，不经过受众、研究、策略、提纲、开头和标题拆分。
- `professional`：受众与研究并行，汇合后依次完成策略、提纲、开头、标题、正文，再交给独立审核；适合重要内容、证据密集内容和需要完整过程审计的任务。

两档都保留稿件版本、调用用量、审核报告和人工最终确认。极速模式不是跳过质量控制，而是把过程压缩成“生成—独立审核”。

## content-ucb1-v2

算法将账号的内容栏目视为多臂老虎机中的候选臂。每篇满足条件的历史作品形成一个样本：同账号、同平台、同内容形式、同数据来源、同观察窗口、自然流量、观察时间可比，且阅读/播放与四项互动数据完整。

单样本回报为：

```text
每千次阅读/播放加权有效互动
= 1000 × (点赞×1 + 收藏×3 + 评论×2 + 分享×3) / 阅读或播放
```

权重是公开、可修改、可审计的产品策略，不冒充平台官方权重。每个已有样本的栏目计算：

```text
UCB = 样本平均回报 + 8 × sqrt(ln(总样本数 + 1) / 栏目样本数)
```

未测试栏目优先进入探索；全部栏目已有数据后选择 UCB 最大者。推荐会标明本次是“探索”还是“利用”，并输出每个候选栏目的均值、探索奖励、UCB、指标引用及排除记录。

这里采用的是受 UCB 思路启发的工程策略：互动回报未归一化为有界奖励，常数 8 为产品参数。因此分数不能解释成统计置信区间，也不声称具有经典 UCB1 的理论遗憾界；需要通过同口径观测来检验实用性。

## 安全与证据边界

- 不预测爆款，不把相关性解释为因果。
- 真实人工记录与模拟数据完全隔离。
- 实验必须由用户接受后才能进入创作上下文。
- 一次只建议改变一个表达变量；实际执行仍由用户负责。
- 修正任一依赖指标后，相关实验自动变为 `superseded`，不能继续用于创作。
- 依赖包含推荐时计分与被排除的记录；未来新样本不改写已冻结的基线。
- 发布只绑定已确认的准确稿件版本；实际形式、栏目和流量类型由用户另行申报，不把计划当执行事实。
- 目标窗口未到、指标缺失或无基线时明确标记；修正后保留失效结果和原指标快照，不伪造增长结论。
- 账号和 owner 双重隔离，其他用户不能引用实验。

## 不可替代的竞争力

页面提供三条项目内路径：极速创作、专业创作、长期运营实验。DeepSeek 是当前可替换的模型执行器，产品竞争力不依赖某个具体模型，而来自两档任务路由、独立审核、证据审计、版本管理、指标失效链和可解释跨期实验。单次文案生成只是入口，系统持续记住“为什么这样写、发布后怎样、下一次验证什么”。
