# 五人试读：直接拿去用

用同一份公开商品资料、同一目标人群和同一推广角度，比较普通 AI 与有迹的真实输出。这里测的是看懂、可信和进一步了解意愿，不是咨询、成交、涨粉或爆款效果。

案例是罗技 M185，无关护肤品品类。[官方资料](https://www.logitech.com/zh-cn/shop/p/m185-wireless-mouse)于 2026-10-04 核对。仅摘录紧凑、双手通用、USB 接收器、系统兼容和有条件的最长续航；未采用效率百分比，也未把含糊表述当成静音证明。事实与限制保存在 [案例资料](m185_case.json)。案例不是品牌授权，不使用官方图片。

## 先得到公平的两份稿

1. 普通 AI 用与系统相同的模型、商品资料、目标人群、目标、选定推广角度和字数限制；允许正常完整的提示词，不故意让基线表现差。若使用不同模型必须记录，不能把差异全归于系统。
2. 将案例 JSON 全文作为资料，使用下方基线提示词。系统也输入同样资料，选择“使用场景”角度，不为系统额外偷偷补资料。
3. 保留各自第一份可用完整稿及失败/重试记录。两份均可做同等限度人工修改，记录次数、修改字符数和耗时。不能挑选更差的普通 AI 稿、只挑系统成功案例。若改稿，盲测用最终实际稿，原始稿留在主持人证据里。
4. 两份统一以纯文本显示，保留各自标题、正文、可见来源和限制。移除工具名字、过程日志及生成者签名，但不能删掉不利内容或修改卖点；记录清理操作。读者不知道哪份来自哪种方法。

普通 AI 提示词（粘贴案例 JSON 后使用）：

> 请根据上面资料，为指定目标人群写一篇小红书推广笔记。使用指定 angle，达到 goal，遵守 constraints 和 format。把产品特点连接到读者使用场景，说明适用条件，给出自然的进一步了解邀请。只使用给定事实，不虚构购买经历、优惠、竞品参数或品牌合作。输出标题和完整正文，不输出写作过程。

## 生成并发给五位同学

把两份真实稿保存为 UTF-8 文本。创建主持人制作记录 JSON：

```json
{"ordinary_ai":{"elapsed_seconds":null,"manual_edit_count":null,"edited_characters":null},"system":{"elapsed_seconds":null,"manual_edit_count":null,"edited_characters":null}}
```

未知数据保留 null，不填零。耗时从提交完整任务到得到可用稿；修改次数是保存的人工改稿轮数，字符数按实际替换、添加、删除字符记录。主持人另记模型、时间、任务 ID、提示词、重试和清理操作。

在项目目录运行：

```bash
python3 scripts/brand_blindtest.py generate --case docs/evaluation/m185_case.json --ordinary /private/tmp/ordinary.txt --system /private/tmp/system.txt --production /private/tmp/production.json --output /private/tmp/brand-readers
```

目录里有 P01 至 P05 五份独立 HTML，用浏览器打开即可；也可打印填写。每位只收到自己的 HTML，不要把整个目录或主持人 JSON 发给读者。A/B 顺序已随机，两个方向相差最多一人；每人映射可能不同，不能统一说 A 是某个系统。稿件来源若在正文里自报身份，主持人必须先清理并记录。

开场只说：“想请你比较两份产品介绍，大约 10 分钟。没有标准答案，不用填写身份信息，可以退出。请独立作答。”不要暗示喜欢哪份，也不要先介绍有迹功能。找真正符合描述或接近的大学生；若不符合，主持人匿名记录偏差。不要把朋友的回答写成商业客户验证。

电子版：填完点“下载我的匿名回答”，把 JSON 发回主持人；没有服务器，也不会自动上传。打印版：主持人按原文转录为同格式 JSON，保留纸表并标明转录，不能补答。原始文件保存在本机 runtime 或私有临时目录，不提交仓库。别收姓名、联系方式或账号；征得同意后才引用匿名原话。

## 汇总真实回答

```bash
python3 scripts/brand_blindtest.py summarize --mapping /private/tmp/brand-readers/主持人专用-不要发给试读者.json --responses /private/tmp/P01-回答.json /private/tmp/P02-回答.json --output /private/tmp/brand-results.json
```

可先汇总两位，报告会列出仍未收回的编号。重复编号、评分缺失、稿件版本变化会报错，不将缺失算零。输出逐人评分、偏好、原话和制作记录。报告建议写“5 位试读者中 X 位更愿意进一步了解系统稿”，同时保留不喜欢的理由和样本限制；不要写为“转化率提高 X%”。零份回答就是尚未验证。
