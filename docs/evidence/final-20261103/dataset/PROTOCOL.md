# 公开真实资料的A/E探索性对照协议

冻结日期：2026-11-03。目标是让同一四角色系统分别在原流程A与三算法启用E下，使用相同官方资料完成300字小红书介绍。六个需求由研究者构造，对象为真实产品/服务；无真实用户访谈、真人满意度或获奖预测。

## 输入与执行

`tasks.json.items`包含REAL-D01、REAL-D02、REAL-H01、REAL-H02、REAL-S01、REAL-S02；数码、家居、教程各两题。合法产品分类分别digital、furniture、general，渠道xiaohongshu、形式note、目标word_count=300。每条`input`仅含topic、audience、material、creation，兼容现有sprint_live_experiment的creation_input投影。

每份素材350—700字符，含研究者独立事实转述和完整限制，不为了降低费用删掉型号、适用条件、未知与禁止结论。相同任务的A/E初始material字节完全相同，input_sha256用于核对；两个配置均能获得相同事实与相同自编写法参考。参考标记synthetic_structure_reference，只提供段落功能，原作者的虚构参数、亲历和独特表达不得进入任务事实。

模型、提示词版本、任务预算与执行环境统一记录。是否重试和如何处理失败必须对两组使用相同规则，保留全部失败、人工等待、审核状态、调用次数和费用。不得仅挑已完成或更好看的稿件。先冻结数据，再记录运行提交、数据哈希、输出哈希；运行后不因结果修改拟定问题和权重。

## 追问不引入额外事实

`fixed_answers.json`在协调人侧封存，初始模型输入不包含答案。E如实际发出追问，标准答案仅重申原素材已知信息或明确“本次仍没有新增资料”；不能给E补充用户个人尺寸、预算、偏好、实测和产品数据。询问与标准问题不对应时统一回复“本次没有相应新增资料；仅按初始材料和原有限制继续”。

A可以不追问。E因询问而增加的交互与调用开销照常计入，不能把模板答复叫做真实用户回答。即便答案不新增事实，E的重述和额外交互仍是流程干预；六题结果只作探索，不能声称严格估计普遍算法因果增益。报告必须说明是同事实边界的流程对照。

## 待人工确认的评价依据

每任务3—5条`proposed_requirements`含r编号、权重、fact_ids和素材定位；这些是研究者拟定清单，状态proposed_gold_pending_independent_human_review。未有人审以前不得称“人工金标准确率”或预先填写覆盖改善。

人工回读官方URL确认事实与条件，再对匿名成稿逐项看是否覆盖及是否串用型号、范围或经验。给定材料支持、与材料冲突、证据不足分开；字面引文命中不等于语义支持或现实真实。成稿若删光事实，应同时记录必要信息遗漏，不能因为没有风险主张就给满分。

A/E文章顺序随机并隐藏配置，真人评分在空表中据实填写；没有参与就保留空白。模型自动评分和研究者快速检查应明确标记，不能替代独立盲评。若报告均值和区间，以任务而非单条句子或多名评审重复评分为独立单位，小样本同时展示逐任务结果与失败例。

## 本次未授权动作

本数据准备环节不调用任何收费模型、不创建或发布GitHub网站/Google表单、不购买产品、不向真人发送邀请、不访问个人账号内容。后续模型运行必须遵守主线程当前有效授权预算与同一累计账本；未知费用停止，历史消费不能清零。产品完成、模型调用结算、真人采用和公开发布分别报告。

## 可复查文件

- tasks.json：六个任务、精确素材span、拟定需求和synthetic参考。
- fixed_answers.json：不新增事实的统一追问答案。
- source_records.json：实际已读官方正文的来源、获取日、有限短摘录、哈希及行定位。
- SOURCES.md：来源目录、版权限制、哈希的实际含义与材料边界。

本协议是实验准备，不是实验结果。正文解析和哈希检查通过不代表用户已确认、文章已通过独立事实核验或某算法一定有效。
