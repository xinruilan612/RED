## 二 算法一句话

模型不直接输出引用文本和字符偏移，只选择 `span_id / excerpt_id / evidence_id`；程序还原原文、编译修改位置、校验证据，再用同一组条件和材料快照复查。

五条硬约束：

| 约束 | 作用 |
| --- | --- |
| 只选 `span_id`，不算字符偏移 | 避免模型改错段落 |
| 读稿必须给 `excerpt_id` | 引文由程序从当前稿取出 |
| 核验/补丁必须给 `evidence_id` | 补丁必须有材料依据 |
| 读稿 `unclear` → 核验必须 `unclear` | 材料有答案不能掩盖稿件没讲清 |
| 无依据返回空补丁 | 不制造“假装修好了” |

## 五 怎么用（录屏/答辩）

1. 打开 http://127.0.0.1:8890/ ，登录后点侧栏 **内容风洞**。
2. 点 **＋ 新建检查**：
   - 粘贴一篇准备发布的稿，或选“导入已有版本”；
   - 填适用读者/场景；
   - 支持材料粘贴可核实原文（入口、参数、限制条件）；
   - 读者问题可填真实反馈，来源选“作者设定”时不会冒充真实反馈；
   - 运行模式选 **真实 AI**（会二次确认费用）。
3. 保存后，在“确认问题卡”页面核对条件，点 **确认这些条件**。
4. 点 **启动真实检查**：先读稿，再核验，出报告（每条都有状态和依据）。
5. 在“检查与修改”里勾选未通过问题，生成局部补丁；查看 diff 和材料依据，勾选采用，保存新版本。
6. 点 **使用原条件复查当前稿件**；复查会保留未解决项，不会删掉困难条件。
7. 点 **结束本次流程并保存报告**，右上角导出报告。

## 六 答辩时怎么讲

- **不要讲**“我们发明了新大模型”；
- 讲“我们做了 **ID 约束的可验证改稿协议**：模型只选 ID，程序还原原文和位置，补丁必须有材料依据，读不清不能被材料答案掩盖，修改后用同一条件复查”。
- 证据分两层：
  1. 产品真跑：本次 5 条条件、1 个实质补丁、复查 2 pass/3 保留；
  2. 研究对照：7 篇完整流程 + 3 篇控制稿，162 次真实调用；如实说有改动的样本少、代理读者不是真人。
- 如果评委追问“创新在哪”，拿 **消融** 说话：自由文本改稿 vs ID 补丁，比较无效补丁率、事实保持率、条件通过率。当前已有 ID 约束的实现和失败拒绝记录，补一组 10 篇中文稿消融即可形成完整算法章节。
