# 有迹三组对照实验 · 预注册评分标准

冻结日期：2026-10-15
适用题库：[gold_set.json](gold_set.json)
状态：**评分标准先于实验冻结**。实验开始后不得修改本文件；若必须修改，须另存新版本并重跑全部三组。

---

## 一 实验目的

回答一个评委一定会问、而项目目前答不出来的问题：

> **多 Agent + 检索，比让大模型直接写一遍，到底好在哪？好多少？值不值这个成本？**

本实验不预设结论。三组用同一模型、同一素材、同一预算上限，只改变协作与检索配置。

---

## 二 三组配置

| 组 | 名称 | 配置 | 材料去向 |
| --- | --- | --- | --- |
| A | 单次直写 | 一次模型调用完成标题+正文+标签；无检索、无多角色 | 全部材料拼进单条提示词 |
| B | 多 Agent · 关检索 | 生产四角色流程；`include_facts=false`、`include_references=false` | 材料仅作为任务背景，不进检索上下文 |
| C | 多 Agent + 分类检索 | 生产四角色流程；三组分类检索开启，向量可用时用向量，否则记录为 BM25 降级 | 材料入库后由 `grouped_retrieve` 检索 |

**控制变量**：同一模型与连接、同一份材料原文、同一预算上限、同一份共享方法文本、同一天内执行。
**必须记录**：代码 SHA-256、提示词版本、模型标识、每组每题的 `retrieval_mode`、token 用量与费用。

## 三 六个指标（全部离线可复算）

| 指标 | 定义 | 方向 | 计算位置 |
| --- | --- | --- | --- |
| 事实支撑率 | 有冻结来源支撑的可核查句 ÷ 可核查句总数 | 越高越好 | `backend/evaluation.py:fact_support_rate` |
| 禁用断言率 | 命中任一禁用断言模式的稿件数 ÷ 稿件总数 | 越低越好 | `forbidden_claim_hits` |
| 要点覆盖率 | 命中的预注册要点数 ÷ 要点总数 | 越高越好 | `expected_point_coverage` |
| 人工修改率 | 人工修改字数 ÷ 成稿字数 | 越低越好 | 需人工记录 |
| 返修轮次 | reviewer 触发 revise 的次数 | 观察项 | 运行回执 |
| 成本与耗时 | 每次调用的 token、费用上界；各阶段墙钟耗时 | 观察项 | `live_calls` 账本 |

### 3.1 可核查句的判定

包含数字、单位或型号类标记的句子视为可核查句（`evaluation.py:CHECKABLE` / `MODEL_TOKEN`）。

**已知局限（如实记录，不隐藏）**：
- 标题里的计数词（如「买前必量 3 处」）会被判为可核查句，可能拉低事实支撑率。这是保守偏差，方向和结论一致，但绝对值不应被当作精确精度。
- 中文同义改写（「家具底部净高」vs「沙发床底净高」）词项重叠低，可能被误判为未覆盖。**这是本指标的主要误差来源**，因此要点覆盖率只用于组间比较，不用于绝对判定。

### 3.2 支撑的判定

句子与某条冻结来源的词项重叠 ≥ 0.5，或句中的单位/型号标记在该来源中逐字出现，即视为有支撑。

**它只证明词汇层面有依据，不证明来源权威、也不证明论证成立。** 不得将本指标表述为「事实核查通过」。

### 3.3 禁用断言的判定：区分「声明缺失」与「违规断言」

稿件写「**无**持妆时长、保湿效果等**未提供数据**」是**正确地声明资料缺失**，与「断言产品有保湿效果」恰好相反。若用朴素正则匹配，前者会被误判为违规，从而把最谨慎的稿件打成最差的稿件。

判定规则：

- 命中位置所在句子若含**缺失声明**（`未提供`、`未给出`、`未列出`、`未包含`、`未说明`、`缺少`、`缺失`、`不含`、`暂不`、`不作`、`不提供`，或 `没有/无` + 20 字内出现 `数据/依据/信息/结论/说明/支持/来源`），记为 **声明缺失**，**不计入违规**。
- 否则计入违规。
- 两类命中都逐条记录在 `forbidden` 字段中，供人工审计；`any_hit` 只由违规命中决定。

**已知局限**：这是句式启发式，不是完整否定解析。像「没有夸大宣传，这款试用 21 天不沾杯」这类句子，裸否定不会豁免其后紧邻的真实断言；但更复杂的多重否定仍可能误判。因此该指标只用于组间比较，报告的结论必须结合逐条记录核查。

## 四 判分流程

1. **自动判分**：`scripts/evaluation_bench.py` 用第三节指标对每题每组自动打分，保留逐句证据。
2. **独立判分（可选层）**：对要点覆盖率与禁用断言率再做一次模型判分（judge），要求：
   - 与生成模型**不同**的模型；
   - 温度 0；
   - 双盲：不告知样本属于哪一组；
   - 使用本文件第三节的判定口径，不得自创标准。
3. **人工抽检**：对 ≥20% 的样本由本人复核自动判分是否合理，记录分歧。
4. **分歧处理**：自动与 judge 不一致时，**以自动判分为准并记录分歧**，不为了让结果好看而择一。

---

## 五 结果表述规范

- 必须报告**全部**样本，包括失败、超时、未生成、为空的结果；不得只留成功样本。
- 三组必须用**同一分母**的主要指标做对比；分母不同的指标单独说明。
- 不得把模拟、替身、dry-run 的结果与真实调用结果混在同一张表里。
- 不得宣称「爆款概率提升」「流量提升 N%」这类本实验无法测量的结论。
- 若 C 组在某个指标上**没有**优于 A/B，必须如实写出，并分析原因（例如：向量未启用、材料本身不含相关事实、样本量不足）。
- 样本量小于 8 题时，只能表述为「初步观察」，不得表述为统计结论。

## 六 预注册的预期与可被推翻的方向

写下来是为了防止事后解释。**以下不是结论，是实验前记录的假设**：

| 假设 | 预期 | 若被推翻说明什么 |
| --- | --- | --- |
| H1 | C 的事实支撑率高于 A | 检索没有实际进入生成，或材料与选题不匹配 |
| H2 | C 的禁用断言率低于 A | 证据约束未生效，提示词或审核门控需要检查 |
| H3 | B 的要点覆盖率高于 A（角色分工带来结构完整性） | 多角色只增加成本、不增加结构 |
| H4 | C 的成本高于 A，但事实支撑率提升幅度大于成本增幅 | 多 Agent+检索在当前场景不划算，应如实写出 |

**H4 若成立「不划算」，结论就是「不划算」。** 如实报告一个负面结论，比编造一个正面结论安全得多，也更有说服力。

## 七 复算方式

任何人拿到 `results-<日期>.json` 与对应的稿件文本，应能在不调用模型、不联网的情况下复算出本文件第三节的全部自动指标：

```bash
runtime/venv/bin/python -m unittest discover -s tests -p "test_evaluation_metrics.py"
```

若复算结果与报告不一致，以报告中的原始证据字段（逐句 `evidence`）为准排查，不得直接改报告数字。
