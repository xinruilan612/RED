# 20任务与30篇结构样本：待人审受控数据包

冻结日期：2026-11-02。用途：三算法机制检查、五配置输出实验准备与人工标注；不是已完成的真实任务实验。

## 已有内容与边界

- `20tasks.json`：20个虚构受控创作任务，数码7、家居7、学习6；首两条D01、H01。顶层为`items`数组。每条包含可直接传给创建接口的`input`，另有`topic/material/audience/answer`便于执行器读取；`reference_example`为同分类受控写法参考，运行器需按现有知识库流程以example导入，不得混进facts或initial material。
- `sources.json`：20份完整事实材料和来源。D01、D02、H01复用项目既有`docs/evidence/evaluation/gold_set.json`的G03、G02、G04；其余17份为本轮自编虚构资料。来源保留JSON指针、文本SHA256；旧容器文件另保留整体SHA256。
- `facts`与`proposed_requirements.support`：按完整资料文本的Unicode码点、左闭右开`[start,end)`定位；不是字节偏移。每条引用应满足`source.text[start:end] == quote`。
- `fixed_answers.json`：固定追问与标准答案，全部为预先拟定的虚构用户条件，不是真人回答。各任务的`answer`是相同答案的执行别名。
- `30structure_samples.json`与`structure_texts/`：30篇自编受控文章，数码/家居/学习各10篇，共156段。正文独立落盘、哈希可核对。包含多种篇章顺序、亲历与对比样式，不是真实创作者文章，不代表平台爆款，也不是人类标注金标。
- `blind_assignment_PRIVATE.json`：100个待生成文章占位的随机盲码，对应20任务×A—E。种子20261102；只有协调者可持有。生成状态全部`not_generated`、文件路径和哈希均为空，不能统计为100份已生成文章。

所有任务`gold_status`均为`proposed_pending_two_human_reviewers`。当前“必需问题、权重、证据对应”只是拟定金标，须由两位人工独立检查再仲裁；不能把这些预填内容称为人工标注结果。当前没有真人参与、评分、耗时或成本校准结果。

`category`是实验分层：digital/home/study；`domain`是已有产品分类：digital/photography/furniture/general。学习任务使用已有general分类，不能把general写作规则误报为新领域语义识别。

标准答案仅在系统真实发出对应补料请求后提供。与预注册问题语义不对应的询问，不得机械灌入整段答案；应记录`unmatched_question`并按统一“暂无相应资料，请收窄”回答。若实验采用统一答案批量补充，须在执行报告注明该干预规则，不能把它当作自然真人交互。

五组配置、模型版本、提示词版本、费用上限、输出字数、重复次数必须在第一次生成前冻结。初始资料和来源对五组相同；补料引入信息的差异是待测干预，应单独报告初始与补料后的指标。禁用联网与自动新增案例。不得用不同模型/不同预算造成的差异来证明算法增益。

## 人审与数据划分

1. 先完成`需求金标审核-空表.csv`，人工确认需求是否合理、权重是否恰当、引文是否真的支持该需求；新增/删除/修改均留理由和版本。
2. 两位结构标注者各持一份独立空表；只能见正文和标注指南，不能见算法预测或生成模板的设计意图。争议由第三人仲裁。角色允许不确定，不能被迫选成算法输出。
3. 在开始调规则前按文章ID冻结开发/测试划分，至少同一原文各段一起分组；不能把一篇文章的段落拆进训练/测试两侧。样本很小，按领域分层报告，并保留逐样本预测和混淆矩阵。
4. 若用全部30篇调规则，则只能报告开发集表现，不得称独立测试。该构造语料与规则可能同源，任何Macro-F1都必须标注“受控合成语料”；后续应另招募经授权真实文章验证泛化。

## 评测口径

- 加权需求覆盖率：人工确认后金标权重作为分母；人工按成稿原句判0/0.5/1，拟定规则冻结后不因组别调整。没有覆盖或答非所问为0；仅部分必要条件为0.5，完整为1。候选池覆盖与成稿覆盖分别统计。
- 有依据主张比例：先人工提取可核对的事实主张，再判资料支持/冲突/不足；分母为全部事实主张。没有事实主张时记NA，同时报告必要信息遗漏，避免删掉所有事实获得高分。这是对给定资料的一致性，不是对现实商品的独立事实核验。
- 结构识别：七类标签的逐类Precision/Recall/F1与Macro-F1；不存在类别记NA并报告实际支持数，不伪造0或1。两人一致性单独计算，仲裁金标与原始两份标注均保留。
- 人工修改比例：Unicode字符级Levenshtein距离 / max(原文字符数,改稿字符数,1)，正文与标题分开；同时报告编辑耗时。不得用字数差替代编辑距离。
- 所有均值/区间以任务为配对单位；多个评审对同一文章的评分不是多个独立任务。小样本报告原始分布和区间，不预先承诺提升或统计显著。

真人验收的空表和具体执行说明位于交付目录`真人验收`。数据验证入口为`validate_dataset.py`；该检查仅验证结构、定位、数量和空标注，不代表模型质量或人工审核完成。
